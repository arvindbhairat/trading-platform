## Actions Taken

### API — Backend (`apps/api/Portfolio/`)

1. **Created `Holding.cs`** — Document models for computed holdings, open lots, and portfolio summary:
   - `Holding`: Symbol, Quantity, AverageBuyPrice, TotalInvested, CurrentPrice, CurrentMarketValue, UnrealizedPnl, UnrealizedPnlPercent, HoldingPeriodDays, Lots
   - `OpenLot`: TradeId, RemainingQuantity, BuyPrice, BuyDate
   - `PortfolioSummary`: TotalInvested, TotalMarketValue, TotalUnrealizedPnl, TotalUnrealizedPnlPercent, PositionCount

2. **Created `HoldingsService.cs`** — FIFO-based holdings computation service:
   - Reads all trades from `ITradeLedgerRepository` ordered chronologically
   - Applies FIFO matching (buys matched against sells in chronological order)
   - Resolves current prices from SQL Server via `IOhlcvRepository.GetLastCandleDateAsync` + `GetDailyAsync`
   - Graceful degradation when price is unavailable (null current price/PNL)
   - `ComputeHoldingsAsync(userId)` — all holdings
   - `ComputeHoldingAsync(userId, symbol)` — single symbol
   - `ComputeSummaryAsync(userId)` — portfolio-level KPIs

3. **Created `PortfolioEndpoints.cs`** — Three REST endpoints:
   - `GET /api/v1/portfolio/holdings` — all open holdings with PnL
   - `GET /api/v1/portfolio/holdings/{symbol}` — single holding detail with lot breakdown
   - `GET /api/v1/portfolio/summary` — portfolio KPIs (total invested, market value, PnL, position count)

4. **Updated `PortfolioExtensions.cs`** — Registered `HoldingsService` as singleton

5. **Updated `Program.cs`** — Wired `app.MapPortfolioEndpoints()` after reconciliation endpoints

### Frontend — Web (`apps/web/`)

6. **Updated `apps/web/src/app/page.tsx`** — Replaced placeholder dashboard with live portfolio dashboard:
   - Portfolio KPI strip (4 cards): Portfolio value, Unrealised P&L, Total invested, Sync status
   - Holdings/positions table: Symbol, Qty, Avg buy, LTP, Invested, Market Value, P&L, Return %, Days held
   - Empty state when no positions exist
   - Reconciliation status side panel: sync status pill, sync message, recovery options, adjustment count, "Sync now" button
   - Data freshness timestamp ("Data as of {IST time}")
   - "Refresh" button that triggers manual reconciliation refresh
   - Error state display
   - Loading state display
   - Navigation integrated with existing `Shell`/`userNavItems`
