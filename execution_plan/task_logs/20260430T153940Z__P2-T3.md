## Actions Taken

### Backend (`apps/api`)

1. **`Users/UserDocument.cs`** — BSON document model for the `users` collection.
   - `UserRole` constants: `"user"`, `"admin"`.
   - `UserApprovalState` constants: `"pending_approval"`, `"approved"`, `"deactivated"`.
   - Fields: `user_id`, `email`, `display_name`, `provider`, `role`, `status` (indexed), `ledger_snapshot_version` (REQ-PORT-031a, init 1), `equity_base_override` (REQ-RME-006c), `created_at`, `updated_at`.

2. **`Users/IUserRepository.cs`** — Interface with `FindByUserIdAsync`, `UpsertOnSignInAsync`, `CountApprovedActiveAsync`, `SetApprovedAsync`, `DeactivateAsync`.

3. **`Users/MongoUserRepository.cs`** — Production implementation.
   - `UpsertOnSignInAsync`: MongoDB `UpdateOne` with `IsUpsert = true`; `$setOnInsert` initialises the record with `pending_approval` and role `user`; `$set` updates `display_name` and `updated_at` on every sign-in without touching `status` or `role`.
   - `CountApprovedActiveAsync`: counts documents where `status = "approved"`.
   - `SetApprovedAsync`: updates only if the user is not already deactivated.
   - `DeactivateAsync`: sets `status = "deactivated"`.

4. **`SysConfig/ISysConfigRepository.cs`** — Interface with `GetTesterCeilingAsync` (default 30) and `GetCurrentPhaseAsync` (default "A").

5. **`SysConfig/MongoSysConfigRepository.cs`** — Reads from `sys_config` collection by `key`; returns defaults when key not found (not yet seeded until P2-T9).

6. **`Users/UserApprovalService.cs`** — Orchestrates ceiling enforcement:
   - Reads current phase; skips ceiling check when phase ≠ "A".
   - Reads ceiling and current approved count; returns `ApprovalResult.CeilingReached` when count >= ceiling.
   - Calls `IUserRepository.SetApprovedAsync`; returns `ApprovalResult.Ok` or `ApprovalResult.UserNotFound`.

7. **`Users/UserExtensions.cs`** — `AddUserManagement()` DI extension; registers all three singletons.

8. **`Auth/AuthEndpoints.cs`** — Modified:
   - OAuth callback: injects `IUserRepository`; calls `UpsertOnSignInAsync` before issuing JWT (REQ-ROLE-001/004).
   - `session/status`: resolves user from `IUserRepository` by `session.UserId`; returns `"pending_approval"`, `"deactivated"`, or `"fyers_required"` (approved, P2-T7 stub) in that priority order.
   - `test-token` (Testing env): upserts and approves `test:user1` so existing session tests continue to exercise the "approved" path.
   - Added Testing-env helpers: `POST /test/users/{userId}/approve`, `/deactivate`, `/seed` — expose `UserApprovalService` for integration tests without requiring admin authentication (wired in P2-T4/P2-T12).

9. **`Program.cs`** — Added `builder.Services.AddUserManagement()`.

### Tests (`tests/api/SignalStack.Api.Tests`)

10. **`InMemoryUserRepository.cs`** — In-memory implementation backed by `ConcurrentDictionary`; respects all state transitions.

11. **`InMemorySysConfigRepository.cs`** — In-memory implementation with mutable `TesterCeiling` and `CurrentPhase` for per-test configuration.

12. **`AuthTestApiFactory.cs`** + **`TestApiFactory.cs`** — Both factories now replace `IUserRepository` and `ISysConfigRepository` with their in-memory counterparts.

13. **`UserIdentityTests.cs`** — 6 new integration tests covering the P2-T3 vertical slice (see Verification section).
