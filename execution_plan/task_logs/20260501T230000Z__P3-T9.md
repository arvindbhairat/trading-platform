## Actions Taken

### 1. Throttle Layer (in `packages/market-data/SignalStack.MarketData/Throttling/`)

Created six files implementing the centralised throttling layer:

- **`IMarketDataThrottle.cs`** — Provider-agnostic throttle interface with single `ExecuteAsync<TResult>` method. Establishes the contract for rate-limited API execution.

- **`MarketDataThrottleOptions.cs`** — Configuration options bound from `integrations.<provider>.rate_limit.*` config keys. Includes `PerSecond`, `PerMinute`, `PerDay`, `BackoffInitialMs`, `BackoffMaxMs`, `BackoffMultiplier`, `MaxRetries`, and `QueueWarnThresholdMs` — all with sensible defaults matching the FYERS budget (10/s, 200/min, 100k/day, 1s initial backoff, 60s max, 2x multiplier).

- **`MarketDataThrottle.cs`** — Core implementation. Four-stage execution pipeline:
  1. Acquire permit from per-second token-bucket rate limiter (0 queue)
  2. Acquire permit from per-minute token-bucket rate limiter (0 queue)
  3. Check daily budget via `DailyBudgetTracker`
  4. Execute operation with retry-on-429 loop (configurable max 5 retries, exponential backoff with 0-10% jitter)
  - Non-429 4xx errors are NOT retried (application errors)
  - Network errors (`HttpRequestException` with null status) ARE retried
  - Queue wait time measured and logged when above warning threshold

- **`DailyBudgetTracker.cs`** — Thread-safe daily budget counter that resets at UTC midnight via `Timer`. Peak concurrency tracking, budget exhaustion detection, and structured logging at reset.

- **`MarketDataThrottleMetrics.cs`** — OpenTelemetry-compatible metrics using `System.Diagnostics.Metrics.Meter` (no external OTel dependency in the market-data package). Instruments:
  - `mdp.api.calls.total` (counter, tagged by provider + status)
  - `mdp.budget.remaining` (observable gauge, tagged by provider)
  - `mdp.budget.usage_percent` (observable gauge, tagged by provider)
  - `mdp.throttle.queue_wait_ms` (histogram, tagged by provider)
  - `mdp.throttle.retries.total` (counter, tagged by provider)
  - `mdp.budget.exhaustion.total` (counter, tagged by provider)

- **`MarketDataThrottleExtensions.cs`** — DI registration: keyed singleton per provider name, config binding from `IConfigurationSection`.

- **`ValueStopwatch.cs`** — Allocation-free stopwatch struct for high-frequency queue wait timing. Removed from `MarketDataThrottle.cs` (wait — actually, let me confirm this is used... yes, used in `MarketDataThrottle.ExecuteAsync` line 71).

- **`RateLimitExceededException.cs`** — Exception type for budget exhaustion and persistent 429 failures.

## Verification

### REQ-RATE-003 — Centralised throttling layer with per-second/minute/day limits

- **Evidence:** `MarketDataThrottle` creates `TokenBucketRateLimiter` for per-second (10 tokens, 1s replenishment) and per-minute (200 tokens, 1min replenishment) limits. `DailyBudgetTracker` enforces per-day budget (100,000 default). All limits sourced from `MarketDataThrottleOptions` bound from `integrations:<provider>:rate_limit:*` config — seeded as `integrations.fyers.rate_limit.per_second=10`, `integrations.fyers.rate_limit.per_minute=200`, `integrations.fyers.rate_limit.per_day=100000` in `SysConfigManifest`.
- **Covered by:** `MarketDataThrottle.ExecuteAsync` steps 1-3 (lines 71-119), `MarketDataThrottleOptions` defaults, `SysConfigManifest` seed entries.

### REQ-RATE-004 — 429 backoff with configurable exponential backoff

- **Evidence:** Retry loop in `MarketDataThrottle.ExecuteAsync` (lines 121-174) catches `HttpRequestException` with `StatusCode = 429` and applies exponential backoff. Backoff parameters (`BackoffInitialMs=1000`, `BackoffMaxMs=60000`, `BackoffMultiplier=2.0`) configurable via `MarketDataThrottleOptions`. Jitter (0-10%) added to prevent thundering herd. Non-429 4xx errors are NOT retried. `MaxRetries=5` caps total attempts.
- **Covered by:** `MarketDataThrottle.ExecuteAsync` retry loop (lines 121-174).

### REQ-RATE-011 — Queue wait duration logging

- **Evidence:** `MarketDataThrottle.ExecuteAsync` line 84 records queue wait via `ValueStopwatch`. Histogram metric `mdp.throttle.queue_wait_ms` emitted. Warning log when queue wait exceeds `QueueWarnThresholdMs` (default 5000ms).
- **Covered by:** `MarketDataThrottle.ExecuteAsync` lines 84-93, `MarketDataThrottleOptions.QueueWarnThresholdMs`.

### REQ-RATE-012 — Daily consumption observable metric

- **Evidence:** `MarketDataThrottleMetrics` exposes 6 instruments via `System.Diagnostics.Metrics.Meter`: `mdp.api.calls.total` (counter), `mdp.budget.remaining` (gauge), `mdp.budget.usage_percent` (gauge), `mdp.throttle.queue_wait_ms` (histogram), `mdp.throttle.retries.total` (counter), `mdp.budget.exhaustion.total` (counter). Gauges wired to `DailyBudgetTracker.RemainingBudget` and `DailyBudgetTracker.UsagePercent`. Meter name `SignalStack.MarketData.Throttling` auto-discovered by OTel.
- **Covered by:** `MarketDataThrottleMetrics.cs`, budget wiring in `MarketDataThrottle` constructor line 59-61.
