# Task Log: P5-T8 — Per-user trade-ledger write lock wired into all ledger writers

## Preconditions

- **Dependencies satisfied:** P1-T13 (lock primitives) and P5-T7 (LADS skeleton) are in `completed_tasks`.
- **Environment assumptions:** .NET 10.0, MongoDB.Driver 3.0.0, Redis via StackExchange.Redis.

## REQ Coverage Attempted

- **REQ-PORT-031** — Trade-ledger write serialisation: every write path acquires the per-user distributed write lock before modifying the trade ledger.
- **REQ-PORT-031a** — `ledger_snapshot_version` incremented atomically after every durable trade-ledger write, never on abort.
- **REQ-PORT-031b** — Fencing token guards every MongoDB write under the lock; stale-write abort prevents version increment (invariant A-11).

## Actions Taken

1. **Created `MongoLedgerSnapshotVersionHelper`** (`packages/config/SignalStack.Configuration/Ledger/`): MongoDB implementation of `ILedgerSnapshotVersionHelper`. Atomically increments `ledger_snapshot_version` on the `users` collection via `$inc`. Logs warning on zero-match (user not found).

2. **Added MongoDB.Driver dependency** to `SignalStack.Configuration.csproj` (v3.0.0) — required by the new helper.

3. **Registered `ILedgerSnapshotVersionHelper` in DI** via `LedgerWriteLockExtensions.AddLedgerWriteLock()` — both API and Worker automatically get the MongoDB implementation registered alongside the existing Redis lock.

4. **Wired LADS `SyncUserAccountAsync`** (`apps/worker/Jobs/AccountSync/LiveAccountDataSyncService.cs`):
   - Injected `ILedgerWriteLock` and `ILedgerSnapshotVersionHelper`.
   - Acquires the per-user lock with `TryNonBlocking` mode (background job: skip on busy).
   - Applies fencing-token filter (`{ "ledger_fence_token": { "$lte": FencingToken } }`) on the fyers_account_sync update.
   - On fencing-token abort (matchedCount == 0), logs warning and does NOT increment version (REQ-PORT-031b invariant A-11).
   - On successful durable write, calls `_snapshotVersionHelper.IncrementAsync()`.

5. **Created worker-side skeleton ledger writers** (4 services):
   - `EodTradeSyncService` — EOD trade-ledger sync (TryNonBlocking).
   - `ManualSyncService` — user-triggered manual sync (WaitFiveSeconds).
   - `AdminRebuildService` — admin rebuild (WaitThirtySeconds).
   - `SingleSymbolBackfillService` — single-symbol backfill (WaitThirtySeconds).
   
   Each follows the lock-acquire → fence-guard → version-increment pattern. Actual sync logic deferred to P5-T9+.

6. **Created API-side skeleton ledger writers** (2 services):
   - `OnLoginSyncService` — on-login FYERS account sync trigger (TryNonBlocking).
   - `ManualAdjustmentService` — manual adjustment (WaitThirtySeconds / U-8 path).
   
   Same lock pattern. Deferred sync logic.

7. **Registered all 6 skeleton services** in DI:
   - Worker `Program.cs`: 4 worker-side writers registered as singletons.
   - API `Program.cs`: 2 API-side writers registered as singletons.
