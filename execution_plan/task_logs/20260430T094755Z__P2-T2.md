## Actions Taken

### Backend (`apps/api`)

1. **`Sessions/SessionDocument.cs`** — BSON document model for the `sessions` collection. Fields: `_id`, `user_id`, `session_token` (= JWT `jti`), `issued_at` (TTL field), `expires_at`, `user_agent`.

2. **`Sessions/ISessionRepository.cs`** — Abstraction with three methods: `CreateSessionAsync`, `FindBySessionTokenAsync`, `FindByUserIdAsync`.

3. **`Sessions/MongoSessionRepository.cs`** — Production implementation. `CreateSessionAsync` uses a MongoDB client session transaction to atomically `DeleteMany` prior sessions for the user then `InsertOne` the new document (REQ-SESSION-002a single-atomic-operation requirement).

4. **`Sessions/SessionExtensions.cs`** — `AddSessionManagement()` DI extension; registers `MongoSessionRepository` as the `ISessionRepository` singleton.

5. **`Sessions/SessionValidationMiddleware.cs`** — Runs after `UseAuthentication()`. For every authenticated request, extracts the `jti` claim and looks it up in `ISessionRepository`. Returns `401 session_revoked` if not found (REQ-SESSION-002: revoked when new login replaces the session; REQ-SESSION-008: expired sessions auto-removed by TTL and then rejected).

6. **`Auth/JwtTokenService.cs`** — Added `IssueTokenWithMeta()` returning `(Jwt, Jti, IssuedAt, ExpiresAt)` tuple alongside the token string. `IssueToken()` delegates to it for backward compatibility.

7. **`Auth/AuthEndpoints.cs`** — Modified:
   - OAuth callback creates a session via `ISessionRepository.CreateSessionAsync` after issuing the JWT.
   - Test-token endpoint (Testing/Development only) also creates a session so `SessionValidationMiddleware` passes in integration tests.
   - Added `GET /api/v1/auth/session/status` (requires Bearer auth): returns `{ state, expires_at }`. P2-T2 stub always returns `fyers_required`; P2-T3/P2-T7 extend the state machine.

8. **`Program.cs`** — Added `builder.Services.AddSessionManagement()` and `app.UseMiddleware<SessionValidationMiddleware>()` (ordered after `UseAuthentication`/`UseAuthorization`, before `CsrfMiddleware`).

9. **`SignalStack.Api.csproj`** — Added `MongoDB.Driver 3.0.0` as a direct `PackageReference` so `MongoSessionRepository` can reference MongoDB types directly.

### Frontend (`apps/web`)

10. **`src/app/pending-approval/page.tsx`** — Approval-pending screen (REQ-SESSION-012/013). Informs the user their account awaits admin approval without exposing any protected content.

11. **`src/app/fyers-required/page.tsx`** — FYERS authentication required screen (REQ-SESSION-010/011/013). Explains that FYERS auth must be completed before any portal feature is accessible.

12. **`src/lib/session.ts`** — Session helpers: `fetchSessionStatus()` (calls `GET /api/v1/auth/session/status`), `getTokenExpiresAt()` (client-side JWT decode for UI only; no signature verification), `minutesUntilExpiry()`. Exports `SessionState` and `SessionStatus` types.

13. **`src/components/SessionExpiryBanner.tsx`** — `"use client"` component. Checks remaining session time every 60 seconds; renders a non-blocking `role="status"` banner with a `/login` link when fewer than `warningThresholdMinutes` remain (REQ-SESSION-007). Default threshold = 30 minutes (matching `sys_config.ui.session.expiry_warning_minutes` default; P2-T9 seeder will seed the live value).

14. **`src/app/auth/callback/page.tsx`** — After storing the JWT, fetches session status and routes: `pending_approval` → `/pending-approval`, `fyers_required` → `/fyers-required`, `deactivated` → `/login?error=account_deactivated`, `active` → `/` (REQ-SESSION-010/011/012/013).

15. **`src/app/page.tsx`** — Includes `<SessionExpiryBanner />` as the first child of `<main>` (REQ-SESSION-007).

16. **`tsconfig.json`** — Added `"paths": { "@/*": ["./src/*"] }` to resolve the `@/` path alias during `tsc --noEmit` and vitest.

17. **`vitest.config.ts`** — Added `resolve.alias` for `@` → `./src` so the path alias resolves in the Vite/vitest module graph.

### Tests (`tests/api`)

18. **`InMemorySessionRepository.cs`** — In-memory `ISessionRepository` implementation backed by `ConcurrentDictionary`. Enforces the single-active-session invariant (removes old session before inserting the new one). Used by all test factories so tests run without a live MongoDB.

19. **`AuthTestApiFactory.cs`** — Updated to replace `ISessionRepository` with `InMemorySessionRepository` so existing auth boundary tests continue to work with `SessionValidationMiddleware` active.

20. **`TestApiFactory.cs`** — Same InMemory session repo replacement; prevents the lazy `IMongoClient` factory from being triggered by the middleware during unauthenticated health/root endpoint tests.

21. **`SessionLifecycleTests.cs`** — 5 new integration tests:
    - `Authenticated_request_with_no_server_session_returns_401_session_revoked` (REQ-SESSION-002a / REQ-SESSION-008)
    - `Authenticated_request_with_valid_session_returns_200` (REQ-SESSION-002a)
    - `Second_login_invalidates_first_session` (REQ-SESSION-002)
    - `Session_status_returns_expires_at_and_state` (REQ-SESSION-007 / REQ-SESSION-011)
    - `Session_status_returns_401_without_authentication`

22. **`__tests__/pages.test.tsx`** — Updated to mock `SessionExpiryBanner` (browser-API component) and fixed the pre-existing `RootLayout > wraps children in body` test which incorrectly called `.find()` on a non-array `children` value.
