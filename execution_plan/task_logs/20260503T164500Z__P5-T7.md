### Reasoned verification details

**REQ-PORT-019 flow:**
1. Worker ticks every `PollIntervalSeconds` (default 60s)
2. `ExecuteCycleAsync` called — checks suspension state first
3. `IsMarketHoursAsync` queries trading calendar for today's sessions, converts IST session window to UTC for comparison
4. Outside market hours → `SkippedOutsideMarketHours` result, no sync performed
5. During market hours → reads `jobs.account_sync.intraday_interval_minutes` from sys_config (fallback: `DefaultIntradayIntervalMinutes`=15)
6. `GetEligibleUsersAsync` finds user records with `status=approved` who also have a FYERS token with `status=active` and `expires_at > now`
7. Each eligible user: checks `fyers_account_sync.last_successful_sync_at`; interval not elapsed → skip; interval elapsed → run sync stub
8. Sync stub (skeleton for P5-T7): upserts `fyers_account_sync` with `last_successful_sync_at`, `last_sync_attempt_at`, `sync_status=completed`

**REQ-PORT-021a flow (suspension lifecycle):**
1. If any per-user sync throws `MongoException` or other exception → `errorCount > 0`
2. `HandleCycleAbortAsync` increments `_consecutiveCycleAborts`, emits OTEL counter `lads.cycle.aborted.total{reason=cycle_error}`
3. At count == 2 (`ConsecutiveAbortWarnThreshold`): warning logged (future P8-T2 System Health widget integration point)
4. At count >= 3 (`ConsecutiveAbortSuspendThreshold`): `ActivateSuspensionAsync` called
   - Sets `_isSuspended = true`, records `_suspendedAt`
   - Inserts `rme_incidents` document: `incident_type=lads_sustained_failure`, `severity=error`, `status=open`
   - Inserts `notifications` document: `notification_type=admin_lads_threshold_breach`, `is_admin_notification=true`
5. On next cycle while suspended → `SkippedSuspended` result, no sync attempted
6. On first error-free cycle → `ResetCycleState()`: sets `_consecutiveCycleAborts = 0`, `_isSuspended = false`, fire-and-forget resolves open incidents to `status=resolved`
