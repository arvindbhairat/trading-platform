### 2. API: AdminIncidentEndpoints
- **File:** [apps/api/Admin/AdminIncidentEndpoints.cs](apps/api/Admin/AdminIncidentEndpoints.cs) (new)
- `GET /api/v1/admin/incidents` — Lists incidents with optional `?status=` filter, pagination (`limit`, `skip`), sorted by `created_at` descending. Returns `incidents[]`, `total_count`.
- `GET /api/v1/admin/incidents/{id}` — Single incident by ObjectId with full detail.
- `PUT /api/v1/admin/incidents/{id}/acknowledge` — Transitions open → acknowledged (step-up required). Writes audit event.
- `PUT /api/v1/admin/incidents/{id}/resolve` — Resolves open/acknowledged incidents (step-up required):
  - For `concurrency_conflict_unresolved` incidents with a position_id: performs **frozen-with-visibility resolution** — reads the current position, validates it's in Suspended state, determines restoration state (Open if entry_price exists, PendingEntry if not), clears suspension fields, restores state, writes step-up-gated audit event.
  - Incident status set to `resolved` with `resolved_at` and `resolved_by`.
  - Writes step-up-gated audit event for resolution.
