## Actions Taken

1. Added `GetNonTerminalByUserIdAsync` to `IPositionRepository` and `MongoPositionRepository` for per-user position queries.
2. Created `CorrelatedIndustryGroup` record — model for industry group deserialization.
3. Created `CorrelatedIndustryGroupOptions` — options class with JSON deserialization and cached default groups (Banking & Finance, Metals, Oil & Gas).
4. Created `IPortfolioHeatCalculator` interface with `CalculateAsync` and `AssertEntryAllowedAsync` methods, plus `PortfolioHeatResult` and `HeatEnforcementResult` records.
5. Created `PortfolioHeatCalculator` implementation:
   - Reads equity base via `IEquityBaseReader`
   - Reads non-terminal positions per user via `IPositionRepository`
   - Computes Total Open Risk = Σ(EntryPrice - StopLoss) × Quantity
   - Computes heat = TotalOpenRisk / AccountEquity × 100%
   - Suspended positions continue contributing per REQ-HEAT-008
   - `AssertEntryAllowedAsync` enforces max heat threshold (REQ-HEAT-003)
6. Registered `IPortfolioHeatCalculator` as singleton and `CorrelatedIndustryGroupOptions` in `RmeModuleExtensions`.
7. Added `risk.correlated_industry_groups` to `SysConfigManifest` with default JSON.
8. Added `risk.correlated_industry_groups` row to `docs/system-config.md`.
9. Fixed test stubs (`DelegatingPositionRepository`, `MongoPositionRepositoryStub`) to implement the new interface method.
10. Wrote 18 unit tests covering: zero positions, single/multiple positions, suspended positions, closed positions excluded, other user positions ignored, zero equity, snapshot contention, custom max heat, invalid stop, pending entry, entry allowed/blocked/at-limit, zero-equity block, and CorrelatedIndustryGroupOptions parsing.
