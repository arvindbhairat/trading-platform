1. **Created `apps/worker/Jobs/EodSignalRunner/` directory** with 7 new files:

   - **`EntrySignalDocument.cs`** — MongoDB document model for the `entry_signals` collection. Carries: `user_id`, `symbol`, `session_date`, combined `signal_type_ids`/`signal_type_names` (REQ-STRAT-015a), `signal_subscription_version_ids` and `signal_code_versions` provenance maps (REQ-STRAT-028), `primary_subscription_id` (REQ-STRAT-015b), `job_run_id`, `generated_at`, optional `signal_data`.

   - **`EodSignalRunnerOptions.cs`** — Configuration options: `PollIntervalSeconds` (300), `BatchSize` (50), `MaxCandlesPerSymbol` (500).

   - **`ISignalEvaluatorRegistry.cs`** — Interface for pluggable evaluator registry. Exposes `GetEvaluator()`, `GetAll()`, `GetCodeVersion()`, `GetAllCodeVersions()`.

   - **`SignalEvaluatorRegistry.cs`** — Implementation that populates from DI-registered `IEntrySignalEvaluator` instances. Includes `CodeVersionAttribute` for stable version strings (REQ-STRAT-025).

   - **`EodSignalRunnerService.cs`** — Core service implementing:
     - Single-pass OHLCV read: fetches all active symbols once, caches in `SymbolCandleCache` (daily, weekly, monthly, rolling3/5/7), evaluates all user subscriptions against cached data (REQ-STRAT-013a).
     - Exponential backoff retry for transient SQL Server read errors (REQ-STRAT-027a): initial 200ms, multiplier 2x, max 10s per attempt, overall budget from `eodsr.db_retry.max_seconds` (120s).
     - User-scoped evaluation: groups active subscriptions by user, activates pending versions before evaluation, evaluates each subscription via registered evaluator, merges combined signals per REQ-STRAT-015a.
     - Provenance: captures `signal_subscription_version_ids` (the version_id active at run time for each contributing subscription) and `signal_code_versions` (from `CodeVersionAttribute` on each evaluator).
     - Atomic outcome: returns `completed` (signals written) or `failed_for_review` (no signals emitted on failure).

   - **`EodSignalRunnerWorker.cs`** — BackgroundService following the DataSyncWorker pattern. Polls `job_runs` for pending EODSR jobs; auto-detects when DS has completed for a session but EODSR hasn't run for the next trading day; creates `job_runs` entries and processes them; writes outcome markers (`completed`, `failed_for_review`, `skipped`, `cancelled`).

   - **`EodSignalRunnerExtensions.cs`** — DI registration: binds `EodSignalRunnerOptions`, registers `ISignalEvaluatorRegistry`, `EodSignalRunnerService`, and `EodSignalRunnerWorker` as hosted service.

### REQ-ID verification

- **REQ-STRAT-013**: `EodSignalRunnerService.RunAsync()` reads active symbols from `symbol_master`, fetches daily/weekly/monthly/rolling OHLCV from SQL Server via `IOhlcvRepository`, and evaluates all active subscriptions via registered `IEntrySignalEvaluator` instances. The evaluation target is the next trading day after the DS-completed session (`ResolveNextTradingDayAsync` resolves from `ITradingCalendarRepository`).
- **REQ-STRAT-013a**: Subscriptions are grouped by `UserId` and evaluated per-user in isolated loops. The single-pass read (`ReadAllSymbolDataAsync`) fetches all OHLCV data once into `SymbolCandleCache` held in process memory for the run duration — no per-(user, subscription) re-fetching.
- **REQ-STRAT-027**: `ReadWithRetryAsync` implements exponential backoff (200ms initial, 2x multiplier, 10s max delay) within a total budget of `eodsr.db_retry.max_seconds` (120s). If retries are exhausted for any symbol, the run returns `failed_for_review` and the caller (`EodSignalRunnerWorker.ExecuteEodSrJobAsync`) writes `failed_for_review` outcome with an admin-facing `completion_hint` stating no signals were emitted. No auto-retry within the same session window.
- **REQ-STRAT-028**: `EntrySignalDocument.SignalSubscriptionVersionIds` captures the version_id active at run time for each contributing subscription. `EntrySignalDocument.SignalCodeVersions` captures the `CodeVersionAttribute` value from each evaluator. Both fields are set at creation and never mutated (the document is written once via `InsertManyAsync`). The `JobRunId` field links back to the originating EODSR `job_runs` entry.
