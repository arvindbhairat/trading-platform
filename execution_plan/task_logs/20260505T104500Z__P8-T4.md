## Actions taken

### Backend: `GET /api/v1/admin/legal-posture`
Created [AdminLegalPostureEndpoints.cs](../../apps/api/Admin/AdminLegalPostureEndpoints.cs) with a new admin-only endpoint that returns:
- `current_phase` — from `operations.phase.current` (via `ISysConfigRepository.GetCurrentPhaseAsync`)
- `approved_user_count` — from `IUserRepository.CountApprovedActiveAsync()`
- `tester_ceiling` — from `operations.phase_a.tester_ceiling` (via `ISysConfigRepository.GetTesterCeilingAsync`)
- `fyers_app_type` — derived from `legal.phase_b.commercial_fyers_configured` sys_config boolean
- `tos_version`, `privacy_version`, `disclaimer_version`, `tester_acknowledgement_version` — from sys_config
- `sebi_opinion` — `received` boolean + `received_date` from `legal.sebi_opinion.*` sys_config keys
- `legal_review_received` — from `legal.phase_b.legal_review_received`
- `runbook_catalog` — `total` (18 per catalog README), `authored` (counted from `docs/operations/runbooks/` directory), `reviewed_in_90_days` (regex match on `audit_events.action_type` starting with `runbook_reviewed` within 90 days)

Registered in [Program.cs](../../apps/api/Program.cs) at line 330.

### Frontend: Legal Posture widget
Updated [admin/page.tsx](../../apps/web/src/app/admin/page.tsx):
- Added `LegalPostureData` interface for the API response
- Added `legalPosture` state + fetch from `/api/v1/admin/legal-posture`
- Replaced the "Platform overview" placeholder card with the full Legal Posture widget
- Widget shows labeled rows for: approved users (with "Near cap" warning when ≥90% of ceiling), FYERS app type, document versions, SEBI opinion status, legal review gate, calendar coverage (referencing existing `coverage` state), and runbook catalog
- Added `Row` component for consistent labeled-row layout
- Added `withinTenPercent` helper for warning threshold
- Card shows accent warning when user count is within 10% of ceiling
- Rows are clickable, navigating to the relevant admin section (/admin/approvals, /admin/config, /admin/calendar)
