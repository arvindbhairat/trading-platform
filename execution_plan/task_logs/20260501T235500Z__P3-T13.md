## Actions Taken

### 1. Created `apps/worker/Jobs/DataSync/DataSyncOptions.cs`
Configuration options class bound to `DataSync` config section with:
- `PollIntervalSeconds` (default 120) — how often the worker polls for pending or auto-detected DS runs
- `RecoverySessionCount` (default 10) — number of past trading sessions to look back for recovery
- `BatchSize` (default 50) — symbols per processing batch
- `BulkInsertBatchSize` (default 1000) — rows per bulk operation

### 2. Created `apps/worker/Jobs/DataSync/DataSyncService.cs`
Core service implementing the DataSync logic:
- **Step 1 — Startup token check (REQ-MARKET-005):** Verifies admin FYERS token is available via `Func<Task<string?>>`. If absent/expired/dirty, aborts with structured Error-level log naming the job, provider, and reason code (`admin_token_absent`, `admin_token_expired`, `admin_token_dirty`). Notification emission (admin_fyers_token_expiry_warning via Telegram + email) is logged as a structured placeholder — actual dispatch deferred to P5 notification infrastructure (P5-T4 NDJ, P5-T5 Telegram bot).
- **Step 2 — Session discovery (REQ-MARKET-009):** Queries the trading calendar for recent trading sessions within the recovery window (default 10 sessions lookback). Filters to past-or-today sessions only. Returns sessions in chronological order (oldest first) for sequential processing.
- **Step 3 — Per-session processing (REQ-MARKET-005a, 006, 013):** For each session from oldest to newest:
  - **Batch boundary token re-check:** Calls `CheckAdminTokenAsync` before each session. If token is unavailable mid-run, exits with `partial_completion_token_expired` recording how many sessions and symbols completed.
  - **Per-symbol OHLCV sync:** Iterates all active (non-archived, non-scan-excluded) symbols. For each symbol, resolves the SQL table suffix via `ISymbolTableMapping`, checks if data already exists for that date, fetches from `IMarketDataProvider.FetchHistoricalOhlcvAsync`, validates the candle per REQ-MARKET-013 rules (High >= Low, all prices > 0, Volume >= 0), and inserts into the `D_` table via parameterised INSERT.
  - **Unavailable symbols (REQ-MARKET-006):** Symbols with no data returned from MDP are skipped; symbols with invalid candles are skipped with a logged warning (REQ-MARKET-013/014).
  - **Weekly/Monthly aggregate recompute:** After all symbols for a session, recomputes `W_` and `M_` tables via SQL temp-table + MERGE for the affected week and month ranges.
- **Data validation (REQ-MARKET-013):** `ValidateCandle()` static method checks: High < Low → invalid; any of Open/High/Low/Close ≤ 0 → invalid; Volume < 0 → invalid. Returns null (valid) or an error description string.

### 3. Created `apps/worker/Jobs/DataSync/DataSyncWorker.cs`
BackgroundService that:
- Polls `job_runs` collection for pending DS jobs (`job_type: "DS"`, `outcome: null`)
- If no pending jobs found, auto-detects whether a DS run is needed by:
  - Querying the trading calendar for recent sessions within the recovery window
  - Checking which sessions already have a DS success marker (`job_type: "DS"`, `outcome: "completed"`, `session_date` field)
  - If unsynced sessions exist, creates a `job_runs` entry with `trigger_source: "auto_detected"` and processes it immediately
- Handles job lifecycle: `in_progress` → `completed` / `partial_completion_token_expired` / `failed`
- Writes structured result document with session counts, symbol counts, skip reasons
- Writes `session_date` field as the success marker for EODSR gating (REQ-MARKET-007)
