## Actions taken

- Added a Next.js middleware in `apps/web` that:
  - generates a per-request CSP nonce,
  - forwards it through the request as `x-nonce`,
  - emits strict portal response headers including CSP, HSTS, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, and same-origin cross-origin isolation headers.
- Removed inline styles from the portal shell and moved baseline styling into `globals.css` so the CSP can keep `style-src 'self'`.
- Added API response hardening in `apps/api/Program.cs`:
  - forwarded-header support,
  - HTTPS redirection outside the test environment,
  - HSTS outside development,
  - baseline security headers on API responses.
- Added a dedicated auth-path fixed-window limiter on `/api/v1/auth/*` with:
  - `10` requests per IP per hour,
  - HTTP `429`,
  - `Retry-After` response header.
- Added a probe endpoint at `POST /api/v1/auth/probe` to make the limiter observable before OAuth flows are implemented in Phase 2.
- Added Azure Front Door + WAF baseline IaC in `infra/azure/frontdoor-waf.bicep` with:
  - `Premium_AzureFrontDoor`,
  - managed default rule set and bot-manager rule set,
  - TLS 1.2 minimum on the custom domain,
  - a WAF rate-limit rule on `/api/v1/auth`.
- Extended the API test file with header assertions and auth-probe rate-limit assertions for the new baseline.
