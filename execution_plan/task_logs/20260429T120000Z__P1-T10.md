## Actions taken

### IaC — Key Vault (`infra/azure/keyvault.bicep`)
- Provisioned Key Vault with `enableSoftDelete: true`, `softDeleteRetentionInDays: 90`, `enablePurgeProtection: true` (REQ-BCP-004).
- `enableRbacAuthorization: true` — RBAC-only, no legacy access policies.
- Network ACL defaulting to Deny; Azure Services bypass only.
- `platform-encryption-key`: RSA-2048 key with 90-day rotation policy and 14-day pre-expiry auto-rotate trigger (REQ-BCP-008).
- `session-signing-key`: RSA-2048 key with 97-day lifetime (90-day active + 7-day overlap for token verification per REQ-BCP-008).
- `intent-hmac-key`: versioned secret stub; comment enforces no-purge policy for audit re-verification (REQ-BCP-008 S-13).
- RBAC role assignments for `Key Vault Secrets User` (readers) and `Key Vault Secrets Officer` (writers) via `secretReaderPrincipalIds` / `secretWriterPrincipalIds` parameters.
- Location constrained to `centralindia` | `southindia` only (REQ-LEGAL-009).

### IaC — SQL Server backup (`infra/azure/sqlserver-backup.bicep`)
- SQL Server with Azure AD-only authentication, TLS 1.2 minimum, private endpoint only.
- `marketdata` database: `requestedBackupStorageRedundancy: 'GeoZone'`, 2-day short-term retention (covers 24h PITR window with margin), 12-hour differential interval, 4-week + 3-month LTR (REQ-BCP-002).
- `backtest` database: `requestedBackupStorageRedundancy: 'GeoZone'`, 7-day short-term retention, 24-hour differential interval, 8-week LTR (REQ-BCP-003).
- Passive failover group (`failoverPolicy: 'Manual'`) between primary (Central India) and secondary SQL Server (South India) — no auto-failover per REQ-BCP-005 Phase A intent (restore target only).
- Azure SQL automatic transaction-log backups (every 5–12 minutes) satisfy the "at least every 6 hours" clause in REQ-BCP-002 without additional configuration.

### IaC — Geo-redundancy scaffold (`infra/azure/backup-geo-redundancy.bicep`)
- Primary Recovery Services Vault in Central India with `storageModelType: 'GeoRedundant'` and `crossRegionRestoreFlag: true` (REQ-BCP-005).
- Secondary Recovery Services Vault in South India (passive restore target, no outbound CRR).
- `market-data-backup-policy`: daily full at 06:30 IST, transaction-log every 6 hours, 5-day + 4-week + 3-month retention (REQ-BCP-002).
- `backtest-backup-policy`: weekly full at 07:30 IST Sunday, log every 24h, 8-week retention (REQ-BCP-003).
- Comment block documents Atlas PITR configuration requirements (cannot be expressed in Bicep; Atlas control plane must be configured manually) (REQ-BCP-001).
