## Actions taken

- Added a shared `packages/config/SignalStack.Configuration` library to centralize bootstrap configuration loading for both the API Service and Worker Service.
- Implemented a bootstrap loader that resolves shared non-secret configuration from an Azure-App-Configuration-style snapshot, resolves Key-Vault-style secret references, and writes an atomic last-known-good cache file.
- Implemented bounded LKG fallback semantics: successful remote reads refresh the cache; remote bootstrap failure warm-starts from cache only if the cache age is within `config.last_known_good.max_age_seconds`; stale-or-missing cache fails closed.
- Added a shared mutable configuration provider so bootstrap values are injected into the application configuration root rather than being read ad hoc from application code.
- Added bootstrap state tracking and the `config.source.last_reached_seconds` observable gauge in the shared configuration meter.
- Added a background refresh service that retries remote configuration reads, updates the mutable configuration snapshot, refreshes the LKG cache, and logs a one-time staleness threshold warning when App Configuration remains unreachable beyond the configured threshold.
- Wired both `apps/api` and `apps/worker` to load shared bootstrap configuration before telemetry setup and to expose the shared configuration meter through OpenTelemetry.
- Added local bootstrap snapshot files for both applications so the slice is runnable in-repo without introducing real secrets.
- Added tests covering remote bootstrap success, Key Vault reference resolution, LKG fallback, stale-cache startup failure, one-time staleness alert behavior, and worker-host registration of the shared bootstrap state.
- Updated `.gitignore` so the new source-controlled `packages/config` library is tracked while its build output remains ignored.
