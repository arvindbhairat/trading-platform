# P3-T4 — Calendar coverage check + admin warning + Legal Posture widget hook

## Preconditions

- **Dependencies:** P3-T3 (trading calendar CRUD + session/non-trading-day distinction) is in `completed_tasks`.
- **Environment:** API builds and tests pass; MongoDB available for calendar collection.

## REQ Coverage Attempted

- REQ-CALENDAR-007 — Calendar coverage check, admin warning, Legal Posture widget integration, A->B phase transition gate.

## Actions Taken

### 1. Backend: Coverage API endpoint (`GET /api/v1/admin/calendar/coverage`)
- Added to `apps/api/Admin/TradingCalendarEndpoints.cs` within the existing `/api/v1/admin/calendar` route group.
- Computes "today" in `Asia/Kolkata` using the existing `IstTimeZone.Instance`.
- Iterates through the next 30 calendar days, filtering to weekdays only (Monday–Friday).
- Fetches all calendar entries in that window via `repo.GetAllAsync()`.
- Returns `{ unconfirmed_count, earliest_unconfirmed_date, unconfirmed_dates, checked_from, checked_to }`.
- A date is "unconfirmed" if it has neither a session record (normal/special/muhurat) nor an explicit non-trading-day marker in the trading calendar collection.

### 2. Backend: Legal Posture widget hook + A->B gate (`PhaseConstraintService`)
- Added `ITradingCalendarRepository` dependency to `PhaseConstraintService` (registered as singleton, same as the existing dependencies).
- Added a calendar coverage violation check inside `DetectViolationsAsync()` that runs when phase is "A".
- If unconfirmed weekdays exist in the next 30 days, emits a `PhaseConstraintViolation` with:
  - `Constraint = "calendar_coverage"`
  - `Severity = "critical"`
  - Message with count + earliest unconfirmed date
  - Suggested action pointing to the Trading Calendar page
- This makes the coverage status available to the future Legal Posture widget (P8-T4) via the existing violation detection pipeline.
- The "critical" severity ensures the phase transition workflow (P8-T3) will block A->B until resolved.

### 3. Frontend: Coverage warning banner on admin calendar page
- Added `CoverageData` TypeScript interface and `coverage` state to `apps/web/src/app/admin/calendar/page.tsx`.
- Fetches coverage data alongside calendar entries in `fetchData()` (parallel `Promise.all` call).
- Renders a persistent non-blocking `Card` with `accent="warn"` when `unconfirmed_count > 0`, showing:
  - Alert-triangle icon
  - Count of unconfirmed weekdays
  - Earliest unconfirmed date (formatted in IST with weekday name)
  - Instructional text to add session records or non-trading-day markers
- Banner clears automatically as admin resolves dates (re-fetches on page refresh).

### 4. Frontend: Coverage information on admin home page
- Added `CoverageData` TypeScript interface and `coverage` state to `apps/web/src/app/admin/page.tsx`.
- Fetches coverage data alongside the transfer recovery summary in `fetchSummary()`.
- Renders a warning `Card` above the dashboard content when `unconfirmed_count > 0`, with:
  - Pill showing unconfirmed count
  - Explanation that unconfirmed dates block A->B transition
  - "Open trading calendar" button linking to `/admin/calendar`
- Added shared `formatDate()` helper function (IST-aware, matching calendar page pattern).
