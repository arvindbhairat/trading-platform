## What Was Built

### Backend — `apps/api/`

**New NuGet packages** (`SignalStack.Api.csproj`):
- `Microsoft.AspNetCore.Authentication.Facebook` 10.0.0
- `Microsoft.AspNetCore.Authentication.Google` 10.0.0
- `Microsoft.AspNetCore.Authentication.JwtBearer` 10.0.0
- `Microsoft.AspNetCore.Authentication.MicrosoftAccount` 10.0.0

**`Auth/JwtTokenService.cs`** — Issues HS256 JWTs using `JsonWebTokenHandler`. Claims: sub, email, name, provider, jti. Config read from DI `IConfiguration`.

**`Auth/AuthExtensions.cs`** — `AddSignalStackAuth` extension:
- Registers `JwtTokenService` singleton
- Configures JWT Bearer validation via `.Configure<IConfiguration>` pattern (reads DI config at request time, not at DI registration time — critical for WebApplicationFactory test scenarios)
- Conditionally registers Google, Microsoft, Facebook OAuth handlers when credentials present
- Configures antiforgery: `X-XSRF-TOKEN` header, `XSRF-TOKEN` cookie (not HttpOnly, SameSite=Strict)

**`Auth/CsrfMiddleware.cs`** — Validates CSRF only for authenticated mutation requests (POST/PUT/PATCH/DELETE where `IsAuthenticated == true`). Returns 403 `{ error: "csrf_validation_failed" }` on failure.

**`Auth/AuthEndpoints.cs`** — Minimal API endpoints:
- `GET /api/v1/auth/providers` — always returns google, microsoft, facebook (REQ-AUTH-011)
- `GET /api/v1/auth/login/{provider}` — OAuth challenge redirect
- `GET /api/v1/auth/callback/{provider}` — OAuth callback; issues JWT; redirects to frontend
- `GET /api/v1/auth/csrf` — sets XSRF-TOKEN cookie, returns request token
- `GET /api/v1/auth/me` — RequireAuthorization(); returns user claims
- `POST /api/v1/auth/me` — RequireAuthorization(); CSRF-validated write probe
- `GET /api/v1/auth/test-token` — Testing/Development only; issues JWT without OAuth
- `POST /api/v1/auth/probe` — unauthenticated probe (CSRF not enforced)

**`Program.cs`** — Added `AddSignalStackAuth`, `UseAuthentication`, `UseAuthorization`, `UseMiddleware<CsrfMiddleware>`, `MapAuthEndpoints`. Version bumped to v0.3.

### Frontend — `apps/web/`

**`src/app/login/page.tsx`** — Three OAuth provider buttons always shown (REQ-AUTH-011).

**`src/app/auth/callback/page.tsx`** — Client component; reads `?token=` from URL, stores it, redirects to `/`.

**`src/lib/auth.ts`** — `storeToken`/`getToken`/`clearToken` (sessionStorage); `getCsrfCookie`; `ensureCsrfToken` (lazy fetch); `apiFetch` (adds Bearer + XSRF header for mutations).

### Infrastructure fix — `packages/config/`

**`BootstrapConfigurationLoader.cs`** — LKG cache write is now best-effort (inner `catch (IOException)`). Previously, a write failure from concurrent test factory startup would fall through to the LKG fallback path, which also failed when the file was locked. Now, a write lock is silently ignored and the primary result is returned normally.

### Tests — `tests/api/SignalStack.Api.Tests/`

**`AuthTestApiFactory.cs`** — New factory; sets JWT secret, issuer, audience; disables LKG caching.

**`TestApiFactory.cs`** — Updated; added JWT secret reference and LKG disable to prevent key-zero error in `SymmetricSecurityKey`.

**`AuthBoundaryTests.cs`** — 6 tests covering all deliverables:
1. Providers endpoint always returns all three providers
2. GET /me returns 401 without Bearer token
3. GET /me returns 200 with valid Bearer token
4. POST /me without CSRF returns 403 with `csrf_validation_failed`
5. POST /me with valid CSRF returns 200
6. Unauthenticated POST probe not challenged for CSRF

## Non-Obvious Decisions

**`.Configure<IConfiguration>` for JWT options:** `WebApplicationFactory.ConfigureWebHost` runs after the DI container is configured, so `builder.Configuration` at DI registration time may not yet contain the factory's in-memory values. Using `.Configure<IConfiguration>` defers reading the secret until the options are first resolved (request time), at which point the DI `IConfiguration` includes all factory overrides. This pattern is the correct solution for any options that need test-overridden configuration in `WebApplicationFactory` scenarios.
