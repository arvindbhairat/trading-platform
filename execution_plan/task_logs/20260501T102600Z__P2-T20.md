## Actions taken

### apps/api — PhaseEnforcementMiddleware
Created `apps/api/PhaseEnforcement/PhaseEnforcementMiddleware.cs`:
- Intercepts requests to `/api/v1/billing`, `/api/v1/payment`, and `/api/v1/invoice` path prefixes.
- When `operations.phase.current` is `"A"`, returns HTTP 403 with `phase_a_restricted` error code.
- When phase is `"B"` or `"C"`, passes through to normal routing.
- Follows the existing `SessionValidationMiddleware` pattern: `RequestDelegate` + `ILogger` in constructor, additional DI (ISysConfigRepository) via `InvokeAsync`.

### apps/api — PhaseConstraintService
Created `apps/api/PhaseEnforcement/PhaseConstraintService.cs`:
- Detects Phase A constraint violations that could result from direct DB manipulation.
- Currently checks: tester ceiling exceeded (approved user count > `operations.phase_a.tester_ceiling`).
- Returns empty list when phase is not `"A"`.
- Data consumed by the Legal Posture widget (P8-T4 / REQ-LEGAL-010).

### apps/api — PhaseExtensions
