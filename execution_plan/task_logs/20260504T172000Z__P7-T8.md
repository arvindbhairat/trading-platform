  - User advisory notifications for unresolved and orphan_ack intents

## Actions Taken

1. **Added `UnresolvedAt` field to `IntentLedgerDocument`** — required by REQ-ORDER-014b field list (`unresolved_at`). Added as nullable `DateTime?` with `[BsonIgnoreIfNull]`.

2. **Extended `IIntentLedgerRepository`** with 7 new methods for LADS reconciliation:
   - `GetPendingIntentsByUserAsync` — query pending intents per user
   - `GetUnreconciledMatchedIntentsByUserAsync` — query callback-matched intents without reconciled_at
   - `ReconcileFromLadsAsync` — promote pending → matched with lads_reconciliation source
   - `StampReconciledAtAsync` — set reconciled_at on callback-matched intents
   - `MarkUnresolvedAsync` — transition pending → unresolved with unresolved_at
   - `GetAllIntentsByUserAsync` — fetch all intents for orphan detection
   - `CreateOrphanAckAsync` — insert orphan_ack intent record

3. **Implemented methods in `MongoIntentLedgerRepository`** — all use `UpdateOneAsync` or `FindAsync` with appropriate filters. Nonce-based matching for all mutations.

4. **Created `IntentReconciliationService`** (worker) — the core reconciliation logic with 4 phases:
   - **Phase 1:** Stamp `reconciled_at` on callback-matched intents when LADS observes a matching trade
   - **Phase 2:** Promote pending intents to matched (`lads_reconciliation`) when LADS finds a matching trade (callback-missed path)
   - **Phase 3:** Timeout stale pending intents past `orders.intent_timeout_minutes` to `unresolved` + user advisory notification
   - **Phase 4:** Detect orphan broker order IDs with no matching intent → create `orphan_ack` record + user advisory
   - All transitions recorded in `audit_events` collection via `IAuditEventRepository`
   - User advisories created via `INotificationWriter` with REQ-LEGAL-006-compliant self-directed language

5. **Wired reconciliation into LADS cycle** (`LiveAccountDataSyncService`):
   - Added `ReadIntentTimeoutMinutesAsync()` to read `orders.intent_timeout_minutes` from sys_config
   - Added Step 2b in `SyncUserAccountAsync` after trade ingestion and FillConfirmedEvent emission
   - Reconciliation runs under a try/catch — failures are logged but don't block the sync progress write

6. **Updated DI registration** (`LiveAccountDataSyncExtensions`):
   - Registered `IIntentLedgerRepository` → `MongoIntentLedgerRepository` (needed by worker)
   - Registered `IntentReconciliationService` as singleton
