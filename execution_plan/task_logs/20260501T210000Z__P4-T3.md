## Actions Taken

### 1. Created Backtesting directory structure
- `apps/api/Backtesting/` — new folder for all backtest engine code

### 2. Data models (`BacktestModels.cs`)
- `BacktestOptions` — input parameters for backtest runs
- `BacktestRunResult` — complete output with all portfolio-level metrics
- `BacktestTrade` — per-trade record with R multiple, PnL, slippage/commission
- `BacktestPositionEvent` — lifecycle events (add/reduce/close)
- `EquityPoint` — equity curve data point
- `SignalResult` / `SignalAction` — signal evaluation DTOs

### 3. Pluggable signal evaluator interface (`IEntrySignalEvaluator.cs`)
- Interface with `SignalTypeId` and `Evaluate()` method
- Allows any signal type (MA crossover, volatility, volume, etc.) to plug into the engine

### 4. MA Crossover evaluator (`MaCrossoverEvaluator.cs`)
- Built-in signal using moving average crossover (configurable fast/slow periods)
- ATR calculation using Wilder's smoothing for stop placement
- Configurable via JSON parameters: `fast_period`, `slow_period`, `atr_period`, `atr_multiplier`

### 5. Execution cost model (`ExecutionModel.cs`)
- Slippage: configurable fraction applied to entry/exit prices
- Commission: percentage of trade value (round-trip)
- Gap risk modeling: when price gaps past stop at open, gap-open price is used as effective fill
- REQ-STRAT-018: results never reported without explicit assumptions

### 6. Backtest engine (`BacktestEngine.cs`)
- Core engine that iterates all active Nifty 500 symbols
- Loads OHLCV via existing `IOhlcvRepository` + `ISymbolTableMapping`
- Evaluates signal per symbol, tracks simulated positions
- Calculates all required metrics:
  - R metrics: R multiple per trade, average R, expectancy in R, drawdown in R
  - Portfolio metrics: win rate, profit factor, Sharpe ratio, Sortino ratio, recovery factor
  - Drawdown: peak-to-trough tracking, max drawdown %
  - Total return: absolute and percentage
- Reads `strategies.backtest.low_confidence_skip_threshold_pct` from sys_config for REQ-STRAT-023
- Reads `strategies.backtest.survivorship_bias_discount_pct` from sys_config for REQ-STRAT-011b
- REQ-STRAT-019/021: minimum session pre-check before evaluating each symbol
- REQ-STRAT-022: tracks skipped sessions in result metadata

### 7. SQL Server persistence (`SqlBacktestRepository.cs`)
- Writes to existing `BT_RunHeaders`, `BT_Trades`, `BT_PositionLifecycle`, `BT_PortfolioPerformance`
- REQ-BTSTORE-001/002: persisted to SQL Server with `BT_` prefix

### 8. In-memory fallback repository (`InMemoryBacktestRepository.cs`)
- For development/testing environments without SQL Server

### 9. API endpoints (`BacktestEndpoints.cs`)
- `POST /api/v1/backtest/run` — launches a backtest with full parameters
- `GET /api/v1/backtest/runs` — lists recent run headers
- `GET /api/v1/backtest/runs/{runId}` — retrieves a specific run
- Input validation: date range, equity, slippage, commission, signal type

### 10. DI registration (`BacktestExtensions.cs` + `Program.cs`)
- `AddBacktestingServices(sqlConnectionString)` — registers engine + repository
- `MapBacktestingEndpoints()` — maps endpoint group under `/api/v1/backtest`
- Protected by `RequireAuthorization()`

### 11. Added `GetDecimalAsync` / `GetLongAsync` to `ISysConfigRepository` / `MongoSysConfigRepository`
- Needed by the backtest engine to read numeric sys_config values

### 12. Fixed pre-existing build errors
- `WeeklyCandleBoundary.cs`: tuple element naming issue
- `ChartEndpoints.cs`: removed unavailable `.WithOpenApi()` calls
- `FyersEndpoints.cs`: fixed `Results.Content` API signature change
