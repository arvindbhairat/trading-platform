## Actions Taken

### 1. Created `apps/worker/Jobs/EodSuccessMarker/IEodMarkerReader.cs`
Interface defining the contract for reading DataSync EOD success markers from `job_runs`:
- `HasCompletedAsync(DateOnly sessionDate, CancellationToken)` — returns `true` when a DS success marker exists for the given session date.
- `GetLatestCompletedSessionAsync(CancellationToken)` — returns the most recent session date with a DS marker, or `null` if none exists.
- `GetCompletedSessionsInRangeAsync(DateOnly from, DateOnly to, CancellationToken)` — returns the set of session dates with markers in a date range.

### 2. Created `apps/worker/Jobs/EodSuccessMarker/EodMarkerReader.cs`
Implementation (`internal sealed`) that queries the `job_runs` MongoDB collection for documents with `job_type: "DS"`, `outcome: "completed"`, and a `session_date` field. Logs a warning if multiple markers are found for the same session (diagnostic for duplicate marker scenarios).

### 3. Created `apps/worker/Jobs/EodSuccessMarker/EodSequencingGate.cs`
Public gate that EODSR (and any other downstream consumer) calls before starting:
- `EnsureDataSyncCompletedAsync(DateOnly sessionDate, CancellationToken)` — checks via `IEodMarkerReader` if a DS marker exists; throws `DataSyncNotCompletedException` if absent.
- Logs pass/fail at `Information`/`Error` level respectively.

### 4. Created `apps/worker/Jobs/EodSuccessMarker/DataSyncNotCompletedException.cs`
Typed exception carrying the missing `SessionDate`. Is `InvalidOperationException` for consistency with .NET conventions.

### 5. Created `apps/worker/Jobs/EodSuccessMarker/EodSequencingGateExtensions.cs`
DI registration extension (`AddEodSequencingGate()`) in the `Microsoft.Extensions.Hosting` namespace:
- Registers `IEodMarkerReader` → `EodMarkerReader` (singleton).
- Registers `EodSequencingGate` (singleton).

### 6. Enhanced `apps/worker/Jobs/DataSync/DataSyncWorker.cs`
Added per-session marker writing in `ExecuteDsJobAsync` for multi-session recovery runs:
- After the main DS job completes with outcome `"completed"`, if `CompletedSymbolsPerSession` contains multiple sessions, writes individual lightweight marker documents per session.
- Each marker: `job_type: "DS"`, `marker_type: "eod"`, `outcome: "completed"`, `session_date: <date>`, `parent_job_id: <jobId>`, `created_at: <now>`.
- Uses `ReplaceOneAsync` with `upsert: true` for idempotency — exactly one marker per session regardless of re-runs.
- Single-session runs rely on the existing main job document's `session_date` field (no separate marker needed).

### 7. Modified `apps/worker/Program.cs`
- Added `builder.Services.AddEodSequencingGate()` call after `AddDataSync` registration with inline REQ-MARKET-007 comment.

### 8. Created `tests/worker/SignalStack.Worker.Tests/EodSequencingGateTests.cs`
8 unit tests covering:
- Gate passes when marker exists.
- Gate throws `DataSyncNotCompletedException` when marker is absent.
- Exception carries the correct `SessionDate` and `SessionDateStr`.
- Exception is `InvalidOperationException` for API consistency.
- Exception message contains the session date and REQ-MARKET-007 reference.
- Uses `FakeEodMarkerReader` (file-scoped) following established test patterns (cf. `DelegatingRmeEventConsumer`, `FakeLedgerWriteLock`).

### 9. Fixed pre-existing build issues in `packages/market-data/`
- Added `System.Threading.RateLimiting` NuGet package reference to `SignalStack.MarketData.csproj` (needed by `MarketDataThrottle` for `TokenBucketRateLimiter`).
- Added `using Microsoft.Extensions.Logging` to `DailyBudgetTracker.cs` (missing implicit using).
- Fixed `ILogger<DailyBudgetTracker>` type mismatch in `MarketDataThrottle.cs` (was passing `ILogger<MarketDataThrottle>` to `DailyBudgetTracker` constructor — both existing files never compiled).
