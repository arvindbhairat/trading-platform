## Actions Taken

1. **Created `PositionDocument` model** (`apps/worker/Rme/PositionDocument.cs`)
   - MongoDB document model for the `positions` collection with `_version` (long, starting at 1)
   - Fields: PositionId, UserId, Symbol, State (PositionState), EntryPrice, CurrentPrice, Quantity, StopLoss, TrailingStop
   - Advisory flags: AddAdvisoryActive, ReduceAdvisoryActive, TrailingStopActive, ExitAdvisoryActive
   - Fencing token field: LedgerFenceToken (REQ-PORT-031b)
   - Timestamps: CreatedAt, UpdatedAt, ClosedAt
   - `CloneWith()` method for pure-function immutability (REQ-RME-CONC-003)

2. **Created `IPositionRepository` interface** (`apps/worker/Rme/IPositionRepository.cs`)
   - `GetByIdAsync(Guid, CancellationToken)` — read by ID
   - `CreateAsync(PositionDocument, CancellationToken)` — insert
   - `UpdateWithOccAsync(PositionDocument, long expectedVersion, long? fencingToken, CancellationToken)` — OCC write
   - `GetNonTerminalAsync(CancellationToken)` — rebuild registry at startup
   - `PositionOccResult` struct with `Success` and `NewVersion`

3. **Created `MongoPositionRepository`** (`apps/worker/Rme/MongoPositionRepository.cs`)
   - `_version` filter: `{ _id: positionId, _version: expectedVersion }` (REQ-RME-CONC-002)
   - Fencing-token extension: `{ ledger_fence_token: { $lte: fencingToken } }` when token provided (REQ-PORT-031b(b))
   - On `MatchedCount == 0`: version reverted, `PositionOccResult(false, 0)` returned
   - On success: version incremented, `PositionOccResult(true, newVersion)` returned
   - `GetNonTerminalAsync`: filters `State != Closed && State != Rejected`

4. **Updated `IRmeEventConsumer` interface** (`apps/worker/Rme/IRmeEventConsumer.cs`)
   - Changed signature from `ConsumeAsync(RmeEvent, CancellationToken)` to `ConsumeAsync(RmeEvent, PositionDocument, CancellationToken)`
   - Return type changed from `IReadOnlyList<RmeOutput>` to `(PositionDocument, IReadOnlyList<RmeOutput>)`
   - Documents pure-function contract per REQ-RME-CONC-003

5. **Updated `RmeEventConsumer`** (`apps/worker/Rme/RmeEventConsumer.cs`)
   - Full (PositionDocument, RmeEvent) → (UpdatedPositionDocument, IReadOnlyList<RmeOutput>) implementation
   - Validates transitions against `ITransitionValidator` using current position state
   - Maps advisory flag updates for price-level breach events
   - Returns `CloneWith()`-produced new instance (no mutation of original)
   - No side effects — outputs describe required actions; channel loop performs writes

6. **Updated `NoOpRmeEventConsumer`** (`apps/worker/Rme/NoOpRmeEventConsumer.cs`)
   - Updated to match new interface signature (reference-only, not registered in DI)

7. **Updated `PositionChannelRegistry`** (`apps/worker/Rme/PositionChannelRegistry.cs`)
   - Added `IPositionRepository` dependency for OCC read/write access
   - OCC retry loop in `ProcessEventWithOccRetryAsync`: read position → invoke consumer → OCC write → retry up to 3× on conflict → log error on exhaustion
   - `ApplyOutputs` helper processes side-effect descriptors (logged in P6-T4; incident/notification wiring deferred to P6-T26)
   - Trailing-stop carve-out rejection preserved (ADR-0003)

8. **Updated `RmeModuleExtensions`** (`apps/worker/Rme/RmeModuleExtensions.cs`)
   - Registered `IPositionRepository → MongoPositionRepository` as singleton

9. **Updated `PositionChannelRegistryTests`** (`tests/worker/.../PositionChannelRegistryTests.cs`)
   - Updated `DelegatingRmeEventConsumer` to match new interface
   - Added `DelegatingPositionRepository` test double
   - Added `MongoPositionRepositoryStub` in-memory stub for OCC/fencing-token tests
   - Added OCC retry tests: successful retry after transient conflict, exhaustion after 3 failures
   - Added fencing-token tests: stale write rejected, valid write succeeds
   - All 57 dedicated tests pass (46 TransitionValidator + 11 PositionChannelRegistry)
