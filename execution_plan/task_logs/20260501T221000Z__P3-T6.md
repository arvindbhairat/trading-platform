## Actions Taken

### Backend changes

1. **Added `Microsoft.Data.SqlClient` package** to `SignalStack.Api.csproj` for SQL Server access.

2. **Created `ISyncHealthRepository`** (`apps/api/Universe/ISyncHealthRepository.cs`) — interface for querying per-symbol `D_` table most recent candle dates.

3. **Created `SqlSyncHealthRepository`** (`apps/api/Universe/SqlSyncHealthRepository.cs`) — SQL Server implementation that queries `INFORMATION_SCHEMA.TABLES` for table existence, then `SELECT MAX([Date])` per symbol. Handles missing tables gracefully (reports as no data/out of sync). Batches queries in groups of 50.

4. **Updated `UniverseExtensions.cs`** — Added overload to `AddUniverseManagement` that accepts an optional SQL connection string. Registers `ISyncHealthRepository` as `SqlSyncHealthRepository` when a connection string is provided, or falls back to a `NoopSyncHealthRepository` that reports all symbols as out of sync.

5. **Updated `Program.cs`** — Reads `ConnectionStrings:SqlServer` from config and passes it to `AddUniverseManagement`.

6. **Added three new endpoints in `UniverseSyncEndpoints.cs`**:
   - `GET /api/v1/admin/universe/sync-health` — Returns per-symbol sync health (last candle date, most recent completed trading session, out-of-sync flag) and total out-of-sync count.
   - `POST /api/v1/admin/universe/reseed` — Finds all out-of-sync symbols, creates a `job_runs` record with `triggered_by: manual_reseed`, rejects if an HDS job is already running.
   - `GET /api/v1/admin/universe/hds-status` — Returns latest HDS job runs (up to 5), with current run status, symbols being processed, and completion state.

7. **Modified commit endpoint** (`POST /api/v1/admin/universe/upload/commit`) — After a successful commit with net-new symbols, auto-creates a `job_runs` record with `triggered_by: universe_upload` referencing the upload ID. Failure to create the HDS record does not fail the commit (logged as warning).

### Frontend changes

8. **Updated `apps/web/src/app/admin/universe/page.tsx`**:
   - Added `SyncHealthEntry`, `SyncHealthData`, `HdsJobRun`, `HdsStatusData` types.
   - Added state for sync health data, loading indicator, reseeding state, HDS status, and polling interval.
   - Added `fetchSyncHealth` — calls the new sync-health endpoint.
   - Added `fetchHdsStatus` — polls the hds-status endpoint; auto-refreshes sync health when a running HDS job completes.
   - Added `startHdsPolling` — starts polling every 5 seconds; used after reseed or commit.
   - Added `handleReseed` — triggers the reseed endpoint and starts HDS polling.
   - Added out-of-sync count banner with reseed button (shown after stale warning).
   - Added HDS progress indicator card showing in-flight job details.
   - Added completed HDS notification card.
   - Added "Sync health" column to the symbol master table (shows "synced", "out of sync", or "—").
   - Updated commit handler to parse `hds_triggered` from response and start HDS polling.
   - Updated Refresh button to also refresh sync health and HDS status.
