## Actions Taken

### New files created (`apps/api/TelegramBot/`)

1. **`TelegramBotOptions.cs`** — Configuration options class bound to `TelegramBot` section.

2. **`TelegramBotDocument.cs`** — MongoDB document model for `notification_bots` collection: `bot_username`, `token_key_vault_ref`, `is_active`, `provisioned_by_user_id`, `provisioned_at`, `last_token_replaced_at`, `last_successful_delivery_at`, `previous_bot_id`. REQ-NOTIFY-015.

3. **`ITelegramBotTokenStore.cs`** — Abstraction for bot token storage: `GetTokenAsync`/`SetTokenAsync`. Production implementation targets Azure Key Vault; local dev writes to bootstrap file.

4. **`LocalDevBotTokenStore.cs`** — Local-development implementation writing to `bootstrap/keyvault.local.json` under the `TelegramBotToken` key — the same file the NDJ reads from, ensuring compatibility without NDJ changes.

5. **`TelegramBotService.cs`** — Core service:
   - `GetActiveBotStatusAsync()` — Returns current bot status including token age and rotation-overdue flag. REQ-NOTIFY-015.
   - `ProvisionBotAsync(token, adminUserId)` — Validates via Telegram `getMe`, deactivates previous active bot, writes new token, inserts new `notification_bots` record, writes audit event. Implements REQ-NOTIFY-022a(c) disable-and-re-enable cycle (sets global_disable=true during validation, false on success, leaves true on failure).
   - `ValidateTokenWithTelegramAsync(token)` — Calls Telegram `getMe` endpoint; returns username on success. REQ-NOTIFY-015.
   - `TestSendAsync(adminUserId)` — Sends test message to admin's linked Telegram account. REQ-NOTIFY-015.
   - `GetTokenRotationInfoAsync()` — Returns token age, rotation threshold, and whether rotation is due. REQ-NOTIFY-022a.
   - `RecordSuccessfulDeliveryAsync()` — Updates last successful delivery timestamp (called by NDJ).

6. **`TelegramLinkingService.cs`** — User linking service:
   - `GenerateTokenAsync(userId)` — Creates single-use time-limited linking token (in-memory with expiry). REQ-NOTIFY-016.
   - `ValidateAndLinkAsync(token, chatId)` — Validates token, registers chat ID on user document, resets dirty/failure state. REQ-NOTIFY-016/018.
   - `UnlinkAsync(userId)` — Clears Telegram chat ID while preserving existing notification records. REQ-NOTIFY-018.
   - `GetLinkStatusAsync(userId)` — Returns link status with masked chat ID. REQ-NOTIFY-017.

7. **`TelegramBotExtensions.cs`** — DI registration: binds options, registers `ITelegramBotTokenStore` (local dev), registers named `HttpClient` for Telegram API, registers `TelegramBotService` and `TelegramLinkingService` as singletons.

8. **`TelegramBotEndpoints.cs`** — Admin API endpoints:
   - `GET /api/v1/admin/telegram-bot` — Bot status (username, token age, delivery timestamp, rotation info). REQ-NOTIFY-015.
   - `PUT /api/v1/admin/telegram-bot/token` — Replace token with step-up check. REQ-NOTIFY-015/022a.
   - `POST /api/v1/admin/telegram-bot/test-send` — Test delivery to admin. REQ-NOTIFY-015.
   - `GET /api/v1/admin/telegram-bot/rotation` — Rotation status. REQ-NOTIFY-022a.

9. **`TelegramLinkingEndpoints.cs`** — User API endpoints:
   - `POST /api/v1/telegram/linking-token` — Generate linking token. REQ-NOTIFY-016.
   - `POST /api/v1/telegram/link` — Validate token + link chat ID (called by bot webhook). REQ-NOTIFY-016.
   - `POST /api/v1/telegram/unlink` — Unlink Telegram. REQ-NOTIFY-018.
   - `GET /api/v1/telegram/status` — Link status for dashboard prompt. REQ-NOTIFY-017.

### Modified files

10. **`apps/api/Program.cs`** — Added `builder.Services.AddTelegramBotServices()` and endpoint registrations for `MapTelegramBotEndpoints()` and `MapTelegramLinkingEndpoints()`.

11. **`apps/api/Notifications/NotificationType.cs`** — Added `admin_telegram_token_rotation_due` and `admin_telegram_global_disable_changed` to admin notification types. REQ-NOTIFY-022a.
