2. **Extended `ISysConfigRepository`** (`apps/api/SysConfig/ISysConfigRepository.cs`): Added `GetSeedVersionAsync()` returning the `platform.seed.version` value or null when absent.

3. **Implemented `MongoSysConfigRepository.GetSeedVersionAsync()`** (`apps/api/SysConfig/MongoSysConfigRepository.cs`): Queries `sys_config` by key and returns the value string.

4. **Created `SeedVersionHealthCheck`** (`apps/api/SysConfig/SeedVersionHealthCheck.cs`): ASP.NET Core `IHealthCheck` that returns `Unhealthy` when the sentinel is absent, tagged `"readyz"`.

5. **Wired API health checks** (`apps/api/Program.cs`): Registered `SeedVersionHealthCheck` with the `"readyz"` tag; `/api/v1/healthz` remains a light liveness check; `/api/v1/readyz` predicates on `"readyz"`-tagged checks so it fails when `platform.seed.version` is missing.

6. **Created `SeedVersionStartupGuard`** (`apps/worker/Hosting/SeedVersionStartupGuard.cs`): Worker counterpart — verifies the sentinel document exists in `sys_config` and throws `InvalidOperationException` if absent, blocking Worker startup.

7. **Wired Worker guard** (`apps/worker/Program.cs`): Registered `SeedVersionStartupGuard` in DI and added the `VerifyAsync()` call after `builder.Build()` and before `host.RunAsync()`.

8. **Updated test double** (`tests/api/SignalStack.Api.Tests/InMemorySysConfigRepository.cs`): Added `SeedVersion` property with default `"v0.3"` and `GetSeedVersionAsync()` implementation.

9. **Created `SignalStack.SqlMigrations`** (`packages/migrations/SignalStack.SqlMigrations/`): FluentMigrator console app with:
   - `InitialMarketData_001`: `symbol_master` table + active-symbol index
   - `InitialBacktest_002`: `BT_RunHeaders`, `BT_Trades`, `BT_PositionLifecycle`, `BT_PortfolioPerformance` tables with indexes
   - Runner that creates database if absent and applies all pending migrations

10. **Added project to solution**: `dotnet sln add` for `SignalStack.SqlMigrations`.

11. **Created `deploy.yml`** (`.github/workflows/deploy.yml`): Deployment workflow with ordered stages:
    - `pre-deploy-verify` — restores production snapshot and runs migrations (production only, REQ-MIGRATION-007)
    - `fluent-migrator` → `mongo-migration` → `seeder` → `deploy-api` + `deploy-worker` (parallel)
    - Post-deployment smoke tests: `/api/v1/healthz` and `/api/v1/readyz`
    - Windows Server 2022 App Service deployment targets

12. **Created `Verify-MigrationSnapshot.ps1`** (`infra/azure/scripts/Verify-MigrationSnapshot.ps1`): PowerShell script for production snapshot restore + migration verification.
