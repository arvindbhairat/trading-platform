# P1-T5 - OpenTelemetry + OTLP wiring + collector dual-replica + saturation policy + fallback endpoint

## Preconditions

- Dependencies satisfied: `P1-T3`, `P1-T4`.
- Environment assumptions:
  - Workspace-write access only.
  - `dotnet` restore/build available locally, but outbound package restore to `https://api.nuget.org/v3/index.json` is blocked in this environment.
  - User-profile `NuGet.Config` under `%AppData%` is not readable from the sandbox, so a repo-local `NuGet.Config` was needed for deterministic restore attempts.

## Actions taken

- Added OTLP telemetry configuration to the API and Worker appsettings with:
  - primary endpoint
  - fallback endpoint
  - config-only fallback toggle
  - bounded export timeout
- Added OTLP wiring for API logs, traces, and metrics using OpenTelemetry exporters.
- Added OTLP wiring for Worker logs, traces, and metrics using OpenTelemetry exporters.
- Added Worker-specific telemetry primitives:
  - startup activity
  - heartbeat counter
  - lease-refresh duration histogram
- Added local dual-collector Docker services and dedicated collector configs for primary and fallback collectors.
- Added repo-local `NuGet.Config` so restore does not depend on an unreadable user-level NuGet config file.
- Added unit tests covering primary-vs-fallback endpoint resolution in both API and Worker.
- Corrected an existing bad API test-project reference path so the solution can resolve the API project correctly during restore/build.

  - `dotnet build SignalStack.sln -c Release --no-restore --nologo`

- Environment workaround used for attempts:
  - `DOTNET_CLI_HOME=C:\poc\.dotnet`

  - `MSBuildEnableWorkloadResolver=false`
- Observed results:
  - Initial restore/build attempts failed before compile because the sandbox could not read `%AppData%\NuGet\NuGet.Config`.
  - After adding `NuGet.Config` and redirecting `APPDATA`, restore reached package resolution but failed with `NU1301` because outbound access to `https://api.nuget.org/v3/index.json` is blocked in this environment.
  - Because restore could not complete, build/test could not be fully executed here.
- Reasoned verification by REQ:
  - `REQ-NFR-008`: API and Worker now both configure OTLP exporters for logs, traces, and metrics, using OTLP as the cross-service export protocol.
  - `REQ-NFR-009`: Both services now target collector endpoints via configuration rather than vendor-specific sinks; infra now includes two local collectors to model the stable collector/gateway layer.
  - `REQ-NFR-009a`: Fallback rerouting is configuration-driven through `Telemetry:Otlp:UseFallbackEndpoint` and the dedicated fallback endpoint value, with no code-path switch needed at failover time.
  - `ADR-0002`: The implementation follows the accepted observability direction by centralizing telemetry on OTLP and keeping collector routing in configuration/infrastructure.
