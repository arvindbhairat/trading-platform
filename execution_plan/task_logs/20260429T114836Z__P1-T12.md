## Actions Taken

1. Created `apps/worker/Rme/RmeEvent.cs` — abstract base record + concrete event types (`PriceLevelBreachedEvent`, `FillConfirmedEvent`, `TrailingStopUpdateEvent`, `DrawdownStateChangedEvent`, `KillSwitchActivatedEvent`) with `LevelType` / `DrawdownLevel` enums. `TrailingStopUpdateEvent` carries the ADR-0003 carve-out comment.

2. Created `apps/worker/Rme/PositionChannelOptions.cs` — `ChannelCapacity` (default 50) and `BacklogWarnDepth` (default 40) bound from `Worker:Rme:Channel` section.

3. Created `apps/worker/Rme/IRmeEventConsumer.cs` — per-event consumer interface; doc-comment describes the pure-function contract that P6-T3 must honour (REQ-RME-CONC-003).

4. Created `apps/worker/Rme/IPositionChannelRegistry.cs` — `EnqueueAsync`, `OpenChannel`, `CloseChannel` with per-method XML docs mapping to REQ-RME-CONC-005 sub-clauses.

5. Created `apps/worker/Rme/PositionChannelRegistry.cs` — implementation:
   - `ConcurrentDictionary<Guid, PositionChannelEntry>` registry.
   - Bounded `Channel<RmeEvent>` per position (single-reader, multi-writer, wait-on-full).
   - One `Task` per active position running a `ReadAllAsync` consumer loop (REQ-RME-CONC-001).
   - `TrailingStopUpdateEvent` rejected with `LogError` in consumer loop (ADR-0003 carve-out).
   - Two OTel observable gauges registered on an injectable `Meter` (defaults to `WorkerTelemetry.Meter`):
     - `rme.channel.backlog_warn_depth` — platform-wide max (REQ-RME-CONC-004).
     - `rme.channel.backlog_depth` — per-position tagged by `position_id`.
   - `internal` constructor accepting a `Meter` for test isolation.
   - `IAsyncDisposable` implementation drains all channels on shutdown.
   - `BacklogWarnDepth` threshold triggers a `LogWarning` on enqueue.
   - `internal GetMaxBacklogDepth()` used as gauge callback and directly tested.

6. Created `apps/worker/Rme/NoOpRmeEventConsumer.cs` — placeholder `IRmeEventConsumer` that logs a warning; replaced in P6-T3.

7. Modified `apps/worker/Program.cs` — registered `PositionChannelOptions`, `IRmeEventConsumer` (NoOp), and `IPositionChannelRegistry` (singleton) with `ValidateDataAnnotations` / `ValidateOnStart`.

8. Created `tests/worker/SignalStack.Worker.Tests/PositionChannelRegistryTests.cs` — 7 tests:
   - `Events_for_same_position_enqueued_from_two_threads_are_processed_serially` — vertical slice; proves max observed concurrency = 1 (REQ-RME-CONC-001).
   - `Events_for_different_positions_are_processed_independently` — cross-position test.
   - `Backlog_warn_depth_gauge_reports_maximum_channel_depth` — blocks consumer, enqueues 2 events, asserts `GetMaxBacklogDepth() == 2` (REQ-RME-CONC-004).
   - `Backlog_depth_is_zero_when_all_channels_are_empty` — empty-registry baseline.
   - `TrailingStopUpdateEvent_is_rejected_and_not_forwarded_to_consumer` — ADR-0003 carve-out.
   - `EnqueueAsync_discards_event_and_logs_warning_when_no_channel_is_registered` — no-channel guard (REQ-RME-CONC-005).
   - `CloseChannel_drains_remaining_events_before_consumer_terminates` — lifecycle (REQ-RME-CONC-005b).
