## Verification Performed

### REQ-SEC-007 — Dependency scanning
- **Reasoning**: `dep-scan` job runs `dotnet list package --vulnerable --include-transitive`; grep on `(Critical|High)` pattern triggers `exit 1`. `npm audit --audit-level=high` exits non-zero on any High+ finding. Scheduled workflow re-runs weekly against `main`.
- A PR introducing a package with a known High CVE would trigger the `grep -qE` match and fail the build.

### REQ-SEC-008 — SAST
- **Reasoning**: `sast` job uses `github/codeql-action` v3 with `security-and-quality` queries for both `csharp` and `javascript-typescript`. Findings are uploaded to the GitHub Security tab. Autobuild handles the C# compile + TS discovery.

### REQ-SEC-009 — Secret scanning
- **Reasoning**: `secret-scan` job runs TruffleHog with `--only-verified` across the branch diff. A committed, verifiable API key or token would fail the scan and block the PR.

### REQ-NFR-014 — Coverage thresholds
- **Reasoning (.NET)**: Coverlet MSBuild `/p:Threshold=70 /p:ThresholdType=line /p:ThresholdStat=Total` causes `dotnet test` to exit non-zero if total line coverage falls below 70%. The existing tests (health endpoint, OTLP config, redaction, singleton coordinator, config loader) exercise the primary code paths in the minimal P1 codebase.
- **Reasoning (TypeScript)**: Vitest `thresholds: { lines: 60, ... }` in `vitest.config.ts` causes `vitest run --coverage` to exit non-zero if coverage falls below 60%. `pages.test.tsx` imports and calls both `page.tsx` and `layout.tsx`, exercising 100% of the current two-file portal source.

### REQ-NFR-016 — Contract diff
- **Reasoning**: `contract-diff` job runs `npm --workspace @signalstack/testing run contract-diff`. With no `.contract.json` files in `contracts/`, the script exits 0 with a "scaffolding pass" message. This verifies the gate runs correctly with no registered contracts (the current state). Adding a snapshot file will automatically activate contract comparison.

### REQ-ACCESS-001 — Axe WCAG 2.1 AA
- **Reasoning**: `axe` job runs `npm run test:axe` which runs `accessibility.test.ts`. The home page HTML (with `lang="en"` and semantic structure) is expected to pass all WCAG 2a/2aa rules. The gate-integrity tests confirm axe *does* detect violations when they are present (missing `lang`, missing `alt`).
