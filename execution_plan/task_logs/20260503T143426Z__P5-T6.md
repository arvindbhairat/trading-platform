## Actions taken

### Backend — Repository enhancements (`apps/api/Notifications/`)

1. **`INotificationRepository.cs`** — Added three new interface methods:
   - `CountUnreadCriticalByUserAsync` — counts unread notifications filtered by the `NotificationType.Critical` set.
   - `GetByUserIdFilteredAsync` — same as `GetByUserIdAsync` but with optional filters: `notificationType`, `symbol`, `dateFrom`, `dateTo`, `deliveryStatus`.
   - `MarkAllAsReadAsync` — bulk marks all unread for a user as read, returns modified count.

2. **`MongoNotificationRepository.cs`** — Implemented all three new methods with MongoDB filter builders.

3. **`NotificationType.cs`** — Added `Critical` static `HashSet<string>` containing the non-suppressible types per REQ-PROFILE-006:
   - `exit_alert`, `gap_risk_alert`, `circuit_limit_alert`, `market_halt_active`, `market_halt_cleared`, `pending_entry_superseded`

### Backend — API Endpoints (`apps/api/Notifications/NotificationEndpoints.cs`)

Created new file with four Minimal API endpoints:

- `GET /api/v1/notifications` — User notification feed with optional query params: `limit`, `skip`, `type`, `symbol`, `dateFrom`, `dateTo`, `deliveryStatus`. Returns DTOs with type labels, critical flag, deep link, and delivery status.
- `GET /api/v1/notifications/unread-count` — Returns `{ total_unread, critical_unread }` for REQ-NOTIFY-014 two-count indicator.
- `POST /api/v1/notifications/{id}/read` — Mark single notification as read.
- `POST /api/v1/notifications/mark-all-read` — Mark all unread for the current user as read.
- `GET /api/v1/notifications/types` — Lists user-facing notification types with labels and critical flag (for the filter dropdown UI).

Endpoints registered in `Program.cs` via `app.MapNotificationEndpoints()`.

### Frontend — Helper function (`primitives.tsx`)

Added `userNavItemsWithNotificationCount(totalUnread, criticalUnread)` — creates a copy of `userNavItems` with the notifications badge set. Shows `"C·T"` format when critical > 0, or just `"T"` when only total unread. Badge tone is `warn` when critical > 0, `info` otherwise.

### Frontend — Notification page (`apps/web/src/app/(user)/notifications/page.tsx`)

Created new page with:
- **Header** with title, unread count summary (Pill showing "X critical · Y unread" or just "Y unread"), and "Mark all read" button.
- **Filter bar** with: type dropdown (populated from `/api/v1/notifications/types`), symbol text input, date range (from/to), delivery status dropdown, and a "Clear" button when filters active.
- **Notification list** with cards showing: unread dot indicator, type label, critical/delivery-failed pills, content text, timestamp (relative), symbol, signal type, timeframe, delivery retry count, error details on failed delivery, deep-link "View" button, mark-as-read button.
- **Pagination** via "Load more" button (50 per page).
- **Empty states** for no notifications and no filter matches.
