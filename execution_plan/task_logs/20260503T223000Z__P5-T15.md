## REQ Coverage Attempted

- **REQ-MARKET-016** — On any failure of the shared-ingestion admin FYERS token, enter asymmetric degraded state.

## Actions Taken

1. **Created `SharedTokenHealthService`** (`apps/worker/Integrations/Fyers/SharedTokenHealthService.cs`):
   - Singleton service that reads admin FYERS token from `fyers_tokens` collection (`user_id == "admin"`, `status == "active"`, `expires_at > now`)
   - Maintains in-memory `IsDegraded` flag with thread-safe state transitions
   - Mirrors state to `sys_config` keys (`ops.degraded_mode.shared_ingestion_token`, `ops.degraded_mode.last_successful_token_at`, `ops.degraded_mode.degraded_reason`) for cross-process visibility by the API tier
   - Writes a one-time `AdminSharedIngestionTokenLost` notification document to the `notifications` collection on first transition to degraded (picked up by NDJ for Telegram dispatch per REQ-MARKET-016(g))
   - Provides `GetTokenAsync()` method for use as the admin token provider delegate
   - Provides `IsTokenHealthyAsync()` lightweight check for workers
   - Auto-resumes on next successful token fetch (`TransitionToHealthyAsync`)

2. **Created `SharedTokenHealthServiceExtensions`** (`apps/worker/Integrations/Fyers/SharedTokenHealthServiceExtensions.cs`):
   - DI registration extension method `AddSharedTokenHealthService()`

3. **Updated `FyersMarketDataProviderExtensions`** (`apps/worker/Integrations/Fyers/FyersMarketDataProviderExtensions.cs`):
   - Replaced the env-var-based `FYERS_ACCESS_TOKEN` provider with a `SharedTokenHealthService`-backed provider that reads from `fyers_tokens` MongoDB collection
   - Falls back to env var on service resolution failure (dev/test safety net)

4. **Updated `LiveMarketScanWorker`** (`apps/worker/Jobs/LiveMarketScan/LiveMarketScanWorker.cs`):
   - Before each scan cycle, checks `SharedTokenHealthService.IsDegraded`
   - REQ-MARKET-016(a): if degraded, logs warning and skips the cycle until token is restored

5. **Updated `DataSyncWorker`** (`apps/worker/Jobs/DataSync/DataSyncWorker.cs`):
   - Before creating or processing any DS job, checks `SharedTokenHealthService.IsDegraded`
   - REQ-MARKET-016(b): if degraded, logs warning and returns early (suspends)

6. **Updated `EodSignalRunnerWorker`** (`apps/worker/Jobs/EodSignalRunner/EodSignalRunnerWorker.cs`):
   - Before creating or processing any EODSR job, checks `SharedTokenHealthService.IsDegraded`
   - REQ-MARKET-016(c): if degraded, writes a `job_runs` document with outcome `"skipped_token_unavailable"` and completion hint

7. **Updated `NotificationType`** (`apps/api/Notifications/NotificationType.cs`):
   - Added `AdminSharedIngestionTokenLost` constant
   - Added to `AdminOnly` hash set

8. **Updated `AdminHomeEndpoints`** (`apps/api/Admin/AdminHomeEndpoints.cs`):
   - Added `GET /api/v1/admin/degraded-mode` endpoint
   - Returns `DegradedModeResponse` with `IsDegraded`, `BannerMessage`, `LastSuccessfulTokenAt`, `DegradedReason`
   - Banner message format per REQ-MARKET-016(g): "Shared-ingestion suspended: admin FYERS token refresh failed — LMDS and DataSync are halted. Last successful token at [timestamp]. Re-authenticate to restore."

9. **Updated `Program.cs`** (worker): Registered `SharedTokenHealthService` service

10. **System architecture docs**: The asymmetric degraded state was already documented in `docs/system-architecture.md` at lines 149-150 (likely added by a previous task or during requirements writing). No changes needed.
