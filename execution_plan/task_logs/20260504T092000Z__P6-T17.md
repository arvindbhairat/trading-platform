- `portfolio-risk-guidelines.md` § Stop Loss Types — Required Stop Types (V1) — Break-Even Stop.

## Actions Taken

1. Added `DefaultBreakevenTriggerR` property to `RmeModuleOptions` (default 1.0, range 0.1–10.0) — maps to `sys_config risk.stop.breakeven_trigger_r`.
2. Created `BreakevenStopLoss.cs` implementing `IStopLoss` with:
   - `Name` returns `"BreakevenStop"`.
   - Primary: reads `CurrentRMultiple` from `AdditionalInputs`; if >= trigger, returns stop at entry price.
   - Fallback: `DefaultFixedStopDistancePct` when R-multiple is below trigger, missing, or wrong type.
   - Guard: clamps fallback to 99% of entry if stop >= entry (long-only invariant).
   - No clamping when breakeven is triggered (stop = entry is the intended behavior per REQ-STOP-009).
   - Rounding: `Math.Round(stopPrice, 2)`.
   - Logging: Debug for triggered/not-triggered paths, Warning for missing R-multiple and clamping.
3. Registered `BreakevenStopLoss` as singleton in `RmeModuleExtensions.cs`.
4. Created `BreakevenStopLossTests.cs` with 17 tests covering:
   - Breakeven triggered at exact trigger threshold (1R).
   - Breakeven triggered above threshold (2.5R).
   - Custom trigger threshold from options (2.0R).
   - Trigger at custom threshold boundary (exactly 2.0R).
   - Fallback when R-multiple below trigger (0.5R).
   - Fallback when R-multiple not provided.
   - Fallback when AdditionalInputs is null.
   - Custom fallback distance (3%).
   - Negative R-multiple (position in loss) falls back.
   - Fallback clamped when distance is 0%.
   - Name property returns "BreakevenStop".
   - Rounding when triggered.
   - Rounding when falling back.
   - Large entry price.
   - Wrong-type AdditionalInputs ignored.
   - Just below threshold (0.999R) not triggered.
   - Just above threshold (1.001R) triggered.
