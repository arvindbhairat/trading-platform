**File:** `apps/worker/Jobs/SloBreachMonitor/SloBreachNotificationService.cs` (new)
- `ReportBreachAsync()` method accepts SLO name, observed p95, target, admin userId, detection time
- Per-SLO cooldown tracked in `ConcurrentDictionary<string, DateTime>` (in-memory, per-process)
- Cooldown logic: first breach per calendar day fires; within-same-day breaches suppressed until cooldown expires; new calendar day re-arms
- Creates `AdminSloBreach` notification document via `INotificationWriter`
- Emits `slo.breach_notification_fired` counter metric with SLO name and breach value tags

### 5. Unit tests

**File:** `tests/worker/SignalStack.Worker.Tests/SloBreachNotificationServiceTests.cs` (new)
- 7 tests covering:

  - Second breach within cooldown is suppressed (no additional notification written)

  - Breach after cooldown expires fires again (via `LastFiredPerSlo` manipulation)
  - New calendar day resets cooldown
  - Breach content includes all required fields (SLO name, p95, target, detection time, disclaimer)
  - Throws on null SLO name
