# Task Log: P5-T13 — WebSocket fan-out infrastructure + degraded-Redis fallback

## Preconditions

- **Dependencies satisfied:** P5-T6 (portal notification feed), P5-T12 (LMDS) are both in `completed_tasks`.
- **Environment assumptions:** Redis connection string resolved via `ConnectionStrings:Redis` or `Redis:ConnectionString` (existing pattern). No .env change needed — consumers use the established resolution.

## REQ Coverage Attempted

- **REQ-NFR-013** — WebSocket fan-out for stop-breach, add/reduce advisory, pending-entry-supersede push events via Redis pub/sub.
- **REQ-DATA-006a(c)(i)** — Degraded fallback when Redis is unreachable: workers log warning + fall through, portal clients surface degradation banner and poll.

## Actions Taken

### API side (apps/api)

1. **Created `Push/PushEvent.cs`** — Push event record model with snake_case JSON serialization. Fields: `event_type`, `user_id`, `occurred_at`, `symbol`, `position_id`, `content`, `deep_link`, `price`, `level_type`, `notification_type`.

2. **Created `Push/PushConnectionManager.cs`** — In-memory `ConcurrentDictionary<string, PushConnectionState>` keyed by connection ID. Supports multiple connections per user. `FanOutAsync` sends push events to all WebSocket connections owned by a given user, removing stale connections on send failure.

3. **Created `Push/PushEndpoints.cs`** — Minimal API endpoint at `GET /ws/push`. Authenticates via JWT in query string (same pattern as PLD's `/ws/pld`). Accepts WebSocket upgrade, registers with `PushConnectionManager`, runs a read loop to detect client disconnect, cleans up on close.

4. **Created `Push/PushFanOutService.cs`** — `BackgroundService` that subscribes to Redis channel `push:events`. On receiving a message, deserializes as `PushEvent` and fans out via `PushConnectionManager.FanOutAsync`. On Redis connection failure, logs warning, retries after 30s. If connection string is missing, loops idle.

5. **Created `Push/PushExtensions.cs`** — DI registration: `AddSingleton<PushConnectionManager>()`, `AddHostedService<PushFanOutService>()`.

6. **Modified `Program.cs`** — Added `using SignalStack.Api.Push`, registered `AddPushNotificationServices()`, mapped `MapPushEndpoints()` after the PLD endpoint.

### Worker side (apps/worker)

7. **Created `Push/IPushEventPublisher.cs`** — Interface with `PublishAsync(...)` accepting event details and `IsConnected` property.

8. **Created `Push/RedisPushEventPublisher.cs`** — Redis-backed implementation publishing to `push:events` channel via `ConnectionMultiplexer`. On Redis failure (connection errors, timeout), logs warning and returns false — caller already persisted the event to MongoDB. Uses `CommandFlags.FireAndForget` for publish. Maintains a lazy singleton `ConnectionMultiplexer` with reconnect on failure.

9. **Created `Push/PushExtensions.cs`** — `AddPushEventPublisher()` DI extension registering `IPushEventPublisher` -> `RedisPushEventPublisher` as singleton.

10. **Modified `Program.cs`** — Added `using SignalStack.Worker.Push`, registered `AddPushEventPublisher()` after LMDS registration.

### LMDS integration (apps/worker)

11. **Modified `LiveMarketScanService.cs`** — Injected `IPushEventPublisher`. Updated `EnqueueBreach` to accept `PositionScanInfo` instead of `Guid` so it has access to user ID, symbol, etc. After enqueuing to the channel registry, publishes a push event via `PublishPushEventAsync`. Maps `LevelType` -> push event type strings: `Stop` -> `stop_breach`, `Add` -> `add_advisory`, `Reduce` -> `reduce_advisory`, `TrailingStop` -> `stop_breach` (with `level_type: "TrailingStop"`). Push publishing is fire-and-forget; failures are logged at warning level per REQ-DATA-006a(c)(i).

### Frontend (apps/web)

12. **Created `lib/live-alerts.ts`** — `LiveAlertsClient` class: connects to `/ws/push?token=...`, receives push events, invokes registered callbacks. On WebSocket close/error, starts REST polling fallback (`GET /api/v1/notifications/unread-count` every 15s) and schedules reconnect every 10s. Provides `refreshUnreadCount()`. Singleton via `getLiveAlerts()`.

13. **Created `components/PushAlertProvider.tsx`** — React context provider wrapping the singleton client. Provides `pushStatus`, `unreadCount`, `isDegraded`, `refreshUnreadCount` to all child components. Starts the client on mount.

14. **Created `components/PushDegradationBanner.tsx`** — Banner component that shows "Live alerts paused — real-time monitoring is temporarily unavailable" when push status is `rest_fallback` or `disconnected`. Auto-hides when WebSocket reconnects.

15. **Created `components/AppProviders.tsx`** — Client-side providers wrapper that nests `PushAlertProvider` and `PushDegradationBanner` above children.

16. **Modified `app/layout.tsx`** — Wrapped `{children}` with `<AppProviders>`. The providers component is a client boundary that manages push state at the app root.

17. **Modified `app/(user)/notifications/page.tsx`** — Added `useEffect` subscribing to `getLiveAlerts().onPushEvent()`. When a push event arrives, refreshes unread count and re-fetches the notification list if the user is on page 0.
