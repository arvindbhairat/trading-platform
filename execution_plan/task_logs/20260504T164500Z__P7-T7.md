### Frontend

5. **FyersButtonWidget.tsx** (new) — React component that:
   - Reads signed payload `data_attributes` and user's FYERS App ID (`window.__FYERS_APP_ID__`)
   - Creates `<fyers-button>` DOM element with all data attributes (including `data-fyers`)
   - Registers `window.fyersCallback` global handler on mount, cleans up on unmount
   - Handles **success path**: widget callback fires with `status="success"` → calls `POST /api/v1/execution/intent/callback` with `status="matched"`
   - Handles **failure path**: widget callback fires with non-success status → calls callback endpoint with `status="submission_failed"`
   - Handles **exception path**: network error during callback API call → logs warning, still surfaces result to user. The intent remains "pending" for LADS reconciliation (P7-T8) to resolve.
   - Manages lifecycle states: rendering_button → awaiting_click → callback_received → updating_intent → success/submission_failed/error
   - UI uses design tokens only (no hardcoded colors/spacing)
   - Never advances position lifecycle — only updates intent ledger status

6. **chart/page.tsx** — Wired FyersButtonWidget:
   - Added `activeFyersOrder` state to track active FYERS order session
   - Updated `handleProceed` to set `activeFyersOrder` when valid signed payload exists
   - Added `handleFyersWidgetDismiss` and `handleFyersWidgetComplete` callbacks
   - Renders `<FyersButtonWidget>` when `activeFyersOrder` is set
