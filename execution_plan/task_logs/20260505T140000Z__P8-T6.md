## Actions taken

### Backend

1. **IUserRepository.cs** — Added `ReactivateAsync(string userId, CancellationToken)` method for REQ-ADMIN-001b
2. **MongoUserRepository.cs** — Implemented `ReactivateAsync` (only transitions deactivated → approved)
3. **IntentLedgerDocument.cs** — Added `ExpiredAccountDeactivated = "expired_account_deactivated"` terminal status constant
4. **AdminUserEndpoints.cs** — Complete rewrite:
   - Enhanced `POST /api/v1/admin/users/{userId}/deactivate` endpoint:
     - Step-up re-authentication check (REQ-SEC-011)
     - Cannot deactivate admin accounts
     - Invalidates all active sessions (deletes from sessions collection)
     - Transitions PendingEntry positions → Suspended (`account_deactivated`)
     - Marks all FYERS tokens as dirty
     - Expires pending/awaiting_confirmation intent_ledger records
     - Audit event with REQ-ADMIN-001c detail counts
   - Added `POST /api/v1/admin/users/{userId}/reactivate` endpoint:
     - Step-up gated
     - Only works on deactivated users
     - Transitions to approved
     - Audit event recorded
     - Note: FYERS token remains dirty; user must re-authenticate
   - Added `POST /api/v1/admin/users/{userId}/signal-suspend` endpoint:
     - Step-up gated
     - Sets `signals_suspended = true`
     - Transitions PendingEntry positions → Suspended (`user_signal_suspended`)
     - Audit event recorded
   - Added `POST /api/v1/admin/users/{userId}/signal-enable` endpoint:
     - Step-up gated
     - Sets `signals_suspended = false`
     - Audit event recorded
     - Suspended positions NOT auto-reinstated per REQ-ADMIN-010
   - Updated `AdminUserEntry` record to include `SignalsSuspended` boolean

### Frontend

5. **Admin approvals page** (`apps/web/src/app/admin/approvals/page.tsx`):
   - Added `signalsSuspended` to `UserEntry` type
   - Added "Signals" column showing "Active" / "Suspended" pill status
   - Added "Enable signals" / "Suspend signals" inline buttons for approved users
   - Added "Reactivate" button for deactivated users (with confirmation dialog)
   - Added step-up handling for all protected actions
   - Updated confirmation dialog messages for each action type
