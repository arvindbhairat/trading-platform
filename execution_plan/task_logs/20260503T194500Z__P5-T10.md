## Actions Taken

1. **Created `ManualAdjustmentDocument`** (`apps/api/Portfolio/ManualAdjustmentDocument.cs`) — MongoDB document model for the `manual_adjustments` collection:
   - Fields: UserId, Symbol, AdjustmentType, QuantityDelta, CostBasisDelta, Reason, RequestedBy, ApprovedBy, AuditEventId, LedgerTradeId, CreatedAt, Notes
   - Permanent audit trail per `docs/data-management.md` — no TTL, no archive

2. **Created `IManualAdjustmentRepository` + `MongoManualAdjustmentRepository`** (`apps/api/Portfolio/`) — repository contract and MongoDB implementation:
   - `InsertAsync` — writes a new adjustment record
   - `GetByUserAsync` — lists adjustments by user (most recent first)
   - `GetByUserAndSymbolAsync` — lists adjustments by user + symbol
   - `GetByIdAsync` — single record lookup
   - Compound index on `(user_id, created_at)` per CollectionCatalogueSpec

3. **Created `ReconciliationEndpoints`** (`apps/api/Portfolio/ReconciliationEndpoints.cs`) — four API endpoints exposing the defined recovery order (REQ-RECON-002):
   - `GET /api/v1/reconciliation/status` — returns sync status from `fyers_account_sync` (last sync time, status, sync request state) + available recovery options in step order + adjustment count
   - `POST /api/v1/reconciliation/refresh` — Step 1: records a user-triggered manual sync request in `fyers_account_sync` with `sync_request_status: "pending"`, records audit event. The worker picks up pending requests.
   - `POST /api/v1/reconciliation/adjustment` — Step 3: creates an audited manual adjustment through the full pipeline: (a) records audit event with action type `manual_adjustment_initiated`, (b) calls `ManualAdjustmentService.ExecuteAsync` to write trade-ledger entry with `isAdjustment: true` and context reference, (c) records `ManualAdjustmentDocument` in `manual_adjustments` collection linked to audit event
   - `GET /api/v1/reconciliation/adjustments` — lists adjustment history, optionally filtered by symbol

4. **Created `PortfolioExtensions`** (`apps/api/Portfolio/PortfolioExtensions.cs`) — DI registration extension method `AddPortfolioServices()` registering `IManualAdjustmentRepository → MongoManualAdjustmentRepository` as singleton

5. **Wired into `Program.cs`**:
   - Added `using SignalStack.Api.Portfolio`
   - `builder.Services.AddPortfolioServices()` after `ManualAdjustmentService` registration
   - `app.MapReconciliationEndpoints()` alongside existing user-facing endpoints
