## Actions Taken

### Backend changes

1. **Added `symbol_health` fields to `SymbolMasterDocument`** — `ConsecutiveFailureCount`, `LastSuccessfulProbeAt`, `LastUnknownSymbolAt` with proper BsonElement annotations and BsonIgnoreIfNull.

2. **Added `UpdateSymbolHealthAsync` to `ISymbolMasterRepository`** — Method accepting optional parameters for each health field; only non-null values are applied via `UpdateDefinitionBuilder.Combine`.

3. **Created `ISymbolProbeClient`** (`apps/api/Universe/ISymbolProbeClient.cs`) — Interface with `ProbeResult` enum (`Success`, `Transient`, `UnknownSymbol`) and `ProbeAsync(string symbol, CancellationToken)` method.

4. **Created `StubSymbolProbeClient`** (`apps/api/Universe/StubSymbolProbeClient.cs`) — Always returns `Success` with debug-level logging. Will be replaced by the real MDP adapter in P3-T8/T9.

5. **Created `SymbolProbeService`** (`apps/api/Universe/SymbolProbeService.cs`) — Main orchestration service:
   - Checks `operations.universe.symbol_probe_enabled` sys_config key
   - Reads batch size and flag threshold from sys_config
   - Processes active symbols in batches through `ISymbolProbeClient`
   - Classifies outcomes and updates per-symbol health via `UpdateSymbolHealthAsync`
   - Creates `job_runs` record with `job_type: SYMBOL_PROBE`, outcome summary, flagged symbols list

6. **Three new endpoints in `UniverseSyncEndpoints.cs`**:
   - `GET /api/v1/admin/universe/work-queue` — Returns probe-flagged symbols where `ConsecutiveFailureCount >= threshold`, with failure history and `high_confidence` tag when also detected as rename candidate. Also returns `probe_enabled` status.
   - `POST /api/v1/admin/universe/work-queue/{id}/resolve` — Resolves a probe flag:
     - `approve_rename`: calls `RenameSymbolAsync`, resets failure count, records audit
     - `mark_delisting`: calls `UpdateMetadataAsync(isArchived: true)`, resets failure count, records audit
     - `dismiss`: records audit with reason, does NOT reset failure count (probe re-flags next run)
   - `POST /api/v1/admin/universe/probe` — Manual probe trigger, returns probe run summary

7. **Registered probe services in `UniverseExtensions.cs`** — `ISymbolProbeClient` as `StubSymbolProbeClient`, and `SymbolProbeService`.

### Worker changes

8. **Created `SymbolProbeWorker`** (`apps/worker/Workers/SymbolProbeWorker.cs`) — BackgroundService that polls every 5 minutes:
   - Checks `symbol_probe_enabled` sys_config
   - Checks if today is a trading day via `ITradingCalendarRepository`
   - Checks `fyers_tokens` for admin's active token issued today
   - Checks `job_runs` for existing probe run today
   - Triggers `SymbolProbeService.RunProbeAsync("fyers_token_refresh")` when conditions met

9. **Updated worker `Program.cs`** — Added `AddUniverseManagement()` and `AddHostedService<SymbolProbeWorker>()`.

10. **Added project reference** from `SignalStack.Worker` to `SignalStack.Api` for access to universe services.

### Frontend changes

11. **Updated `apps/web/src/app/admin/universe/page.tsx`**:
    - Added `WorkQueueItem` interface with probe flag fields
    - Added state: `workQueue`, `loadingWorkQueue`, `probeEnabled`, `resolvingItem`
    - Added `fetchWorkQueue` — calls the work-queue endpoint
    - Added `handleResolveItem` — calls the resolve endpoint, refreshes work queue and symbol list
    - Added probe disabled banner (accent="warn") shown when `symbol_probe_enabled` is false
    - Added Work Queue card with header showing item count badge
    - Added `WorkQueueItemCard` sub-component with:
      - Type badge ("Probe flag"), optional "High confidence" badge
      - Symbol name, company name, consecutive failure count
      - Three action buttons: "Approve rename", "Archive symbol", "Dismiss"
      - Inline forms for each action (new symbol input, confirmation, reason input)
    - Updated Refresh button and initial load effect to include work queue
