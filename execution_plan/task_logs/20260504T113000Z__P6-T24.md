## Actions taken

1. Created `apps/api/Backtesting/RmeConfigParser.cs` — `internal static` class that parses RME profile JSON and computes stop price + quantity. Supports `fixed` and `atr` stop types, `fixed_percentage` sizing model. Falls back to legacy `entryPrice * 0.95m` + qty=1 on null/empty/invalid config.

2. Created `apps/api/Backtesting/BteRmeParityResult.cs` — result records (`BteRmeParityResult`, `ScenarioDivergenceDetail`) for parity check output.

3. Created `apps/api/Backtesting/BteRmeParityService.cs` — parity check service with 5 synthetic scenarios (fixed 2%, fixed 1%, ATR 2x, ATR 3x, ATR 1.5x high vol). Reads `operations.bte_rme_parity.enabled` toggle and `risk.parity.divergence_threshold_pct` from sys_config. On divergence: records audit event (`bte_rme_parity_failure`) + admin notification (`ObjectId.Empty` broadcast, `AdminBteRmeParityFailure` type).

4. Modified `apps/api/Backtesting/BacktestEngine.cs` — `OpenPosition` accepts `int quantity` parameter; `SimulatedPosition` has `Quantity` property; `ClosePosition` uses `pos.Quantity` for PnL. Entry logic uses `RmeConfigParser.ComputePositionParameters` when `RmeConfigurationJson` is provided.

5. Modified `apps/api/Notifications/NotificationType.cs` — added `AdminBteRmeParityFailure` constant and registered in `AdminOnly` set.

6. Modified `apps/api/Backtesting/BacktestExtensions.cs` — registered `BteRmeParityService` as singleton, wired `MapParityEndpoints()`.

7. Created `apps/api/Backtesting/ParityEndpoints.cs` — `POST /api/v1/backtest/parity` admin-only endpoint.

8. Created `tests/api/SignalStack.Api.Tests/BteRmeParityCheckTests.cs` — 9 xunit tests directly testing `RmeConfigParser.ComputePositionParameters` against hand-calculated reference values.

9. Created `.github/workflows/bte-rme-parity.yml` — nightly 02:00 UTC schedule + `workflow_dispatch` support; builds + runs parity tests with `FullyQualifiedName~BteRmeParityCheckTests` filter; `failure()` step reports outcome.
