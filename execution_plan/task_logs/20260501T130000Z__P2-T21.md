## Actions taken

1. **Created `apps/api/PrivacyRequest/` feature folder** with:
   - `PrivacyRequestDocument.cs` — MongoDB document model (TicketId, Type, RequesterEmail, Status, AcknowledgedAt, CompletedAt, ResolutionNotes, timestamps). Includes `RequestType` and `RequestStatus` constant classes.
   - `IPrivacyRequestRepository.cs` — Interface for DSAR ticket CRUD (ListAsync, FindByTicketIdAsync, CreateAsync, AcknowledgeAsync, UpdateStatusAsync, CompleteAsync, GetNextSequenceAsync).
   - `MongoPrivacyRequestRepository.cs` — MongoDB implementation using counters collection for ticket ID sequence (`DSAR-{N}`). Uses `FindOneAndUpdate` with `$inc` for atomic sequence generation.
   - `PrivacyRequestEndpoints.cs` — 7 admin endpoints under `/api/v1/admin/privacy/`: list, create, get-detail, acknowledge, process-access (data export), process-erasure (redaction), complete. Includes `BuildDataExport` for access requests with profile + consent_history. Uses `IsAdminAsync` helper.
   - `PrivacyRequestExtensions.cs` — DI registration extension method.

2. **Added `RedactPersonalDataAsync` to user repository**:
   - `apps/api/Users/IUserRepository.cs` — new method signature.
   - `apps/api/Users/MongoUserRepository.cs` — sets Status=deactivated, redacts Email/DisplayName/Provider, nulls LinkedIdentities/EquityBaseOverride, preserves consent/ToS acceptance facts.

3. **Wired up in Program.cs**:
   - Added `using SignalStack.Api.PrivacyRequest;`
   - `builder.Services.AddPrivacyRequestManagement();`
   - `app.MapAdminPrivacyRequestEndpoints();`

4. **Created admin privacy requests page** (`apps/web/src/app/admin/privacy-requests/page.tsx`):
   - 4 view modes: list (ticket table with SLA indicators), create (form), detail (ticket info + action buttons per status/type), erasureConfirm (irreversibility warning), export (JSON display + download).
   - Uses Shell/SideNav layout pattern.

5. **Updated navigation** — added `"privacy-requests"` entry to `adminNavItems` in `primitives.tsx`.

6. **Created in-memory test repositories**:
   - `InMemoryPrivacyRequestRepository.cs` — ConcurrentDictionary + Interlocked.Increment for sequence.
   - `InMemoryAuditEventRepository.cs` — ConcurrentBag-based.

7. **Wrote `DataSubjectRightsTests.cs`** with 5 integration tests:
   - `Erasure_redacts_personal_identifiers_and_preserves_audit_trade_records` — full erasure flow via repos.
   - `Access_request_generates_data_export_with_profile_and_consent_history` — access data export shape.
   - `Privacy_requests_endpoint_requires_admin_and_returns_tickets` — HTTP list endpoint.
   - `Non_admin_user_cannot_access_privacy_endpoints` — 403 guard for non-admin users.
   - `Erasure_via_http_endpoint_type_checked` — type guard returns 422 on wrong type; required CSRF token handling for POST.

8. **Fixed CSRF issue** in the HTTP type-check test — authenticated POST requests go through `CsrfMiddleware` which validates anti-forgery tokens. Added cookie-aware client and `/api/v1/auth/csrf` token fetch before the mutation request.

9. **Updated test factories** (`AuthTestApiFactory.cs`, `TestApiFactory.cs`) — replaced `IAuditEventRepository` and `IPrivacyRequestRepository` with in-memory implementations.
